# AI 脚手架防幻觉设计 — 12 条机制(Euan-Flutter 实证)

> 核心认知:**幻觉不是模型缺陷,是信息缺口的必然产物**。模型在缺口上会用「最像真的」内容补位。
> 脚手架的职责 = 把每个缺口要么填上机械事实,要么钉上显式禁令,让「编造」无处落脚。
> 每条机制都标了本项目的实证(✓=正面证据,✗=缺了这条时的翻车)。

## A 类:堵「接口幻觉」(两个 AI 各自想象对方)

1. **契约 fixtures 双端咬合**:前后端消费**同一份 JSON 文件**做断言,接口形状无法「各自记忆」。
   ✓ Run #2:前端怀疑 PATCH 响应形状,合流验证零改动闭合。
   ✗ Run #3:fixture 的**排序语义**没冻结(只锁了形状),两轨各信一边,合流撞车——教训:**冻结要连语义一起冻**(排序/上限/空值/口径)。
2. **悬点显式化**:轨道报告强制带「契约悬点」栏——AI 必须把假设交出来,而不是埋进代码。
   ✓ Run #4:13 个悬点合流对账全相容,零返工;悬点栏让 display_name 可空性这种地雷在合流前就摆上桌面。
3. **参考模式指针**:「照 customers-repo.ts 的 cursor 写法」替代三段文字描述。既有代码是不会说谎的规格。

## B 类:堵「状态幻觉」(AI 记错项目进行到哪了)

4. **单一状态写者**:progress.yaml 只有 orchestrator 写;轨道 agent 不写状态、不 push。多写者=状态漂移=后续所有推理建立在错误前提上。
5. **自包含 phase 卡**:setpoint + 验收 + 禁区 + 指针全部卡内解决,`self_contained: true` 是承诺——执行者**不需要回忆**会话历史。上下文断了(compaction/断连)也能原地续跑。**长 phase / 跨会话多 Loop**:在 phase 卡内维护 **append-only Loop 台账**(日期·目标·验收命令·结果),新会话读 progress.next + 台账最后一行续跑——模板见 kit/phase-card-template §2b(IPONews 2026-07-16 实证)。
   ✓ 本项目跨 compaction、跨 API 断连多次,零迷路。
6. **disturbance = 显式负空间**:「不许碰 app/」「不许发明业务规则」「通知=纯客户端,别在后端做」。AI 的幻觉经常以「顺手多做」的形态出现,禁区条款与验收标准同权重。

## C 类:堵「完成幻觉」(声称做了但没做/没验)

7. **TDD 铁律**:没有失败测试不许写生产代码。测试先红后绿 = 行为规格先于实现存在,「我觉得逻辑对了」不再是过关条件。
8. **验证后才说完成**:任何「完成」声明必须附**验证命令的实际输出**(测试计数行/curl 响应),禁止「应该没问题」。
   ✓ 每轨报告都带输出末行;S5b 报告里 Stripe LIVE 标 ⏸ 挂账而非谎称走通。
9. **独立对抗审查**:切片收口由另一个带找茬心态的 agent 复核,failed→respond→passed 留痕。第一个 AI 的 checkbox 自评不可信——它有「让自己通过」的结构性动机。
   ✓ S2 审查抓到 T17 重写时被误删的并发双确认测试(Critical 级),主执行者自己完全没意识到。
10. **挂账文化**:外部依赖缺位(Stripe key/DNS)时,验收项标 ⏸ + 写清事后验证步骤。给 AI 一条「诚实但不算失败」的出路,它就不需要伪造。**prompt 里预先写明「严禁伪造证据」比事后抓假更便宜。**

### C 附:完成幻觉子类 · integration-gap(定义齐全 ≠ 接线生效)

> 源流:Euan D21 2026-07-23(主题/组件死代码) + 2026-07-26(CODEOWNERS `@maintainer` 三周空转);digest wiring-anchor-def-not-integration ∪ guardrail-entity-must-resolve。

与「压根没测」不同:**形状测试全绿、文档写着「已配置」**,但消费方/平台从未真正挂上。两条机械防线:

1. **接线锚(代码侧)**:凡新建共享组件 / 主题 / 常量,交卷前必须有一条测试——pump **真实消费方**断言效果生效,并**变异一次**(拆掉接线该锚必须红)。只验「常量/组件自身形状」挡不住死代码。
2. **实体解析(配置侧)**:凡在配置里写实体名的护栏(CODEOWNERS / 审批人 / 告警接收人 / webhook 目标),落地时做一次**实体存在性验证**(API 查询或一次真实触发)并留证据;文档写明生效边界,禁止把「已配置」叙述成「已生效」。(Euan:八处 `@maintainer` 解析不到 handle,自动 request review 全程空转,而 CONTRIBUTING 白纸黑字写着已生效。)

### C 附2:测试锚通则 · 锚必须能判别(语义层 > 文本层)

> 源流:Euan 2026-07-29 wrangler.toml routes 假绿;与接线锚「变异必须红」同族,介质从代码扩到结构化配置。

对 **TOML/YAML/JSON** 等结构化配置的测试锚必须打在**语义层**:能走真解析器就走解析器;宿主语言拿不到解析器时,退而做**位置/结构级判别**(如 routes 必须出现在第一个 `[段]` 之前),并**反向验证**——把配置改坏,锚必须红。纯文本 grep「字符串在文件里」证明不了「解析器认它」——`routes` 写在 `[assets]` 段后会被解析为 `assets.routes` 子键,工具完全不认,文本断言照样全绿。

### C 附3:运行面 · 配置勾选 / 日历开火 ≠ 事件已到

> 源流:SalesDashboard 2026-08-15(launchd 已装且 runs=1 但 exit=1,Graph 没拉到);onboard-bot-lark 2026-08-15(权限已批、审批已过,wrangler tail 零条飞书 POST;共用 Hermes bot URL 会静默吞回调)。digest config-surface-green-is-not-runtime。

C 附写的是「定义齐全 ≠ 接线生效」(代码/配置实体)。本条扩到**外部系统的运行面**:平台绿勾、agent 已 load、日历已开火,都只证明控制面动过,不证明事件到了、产物在了。

1. **定时/日历任务**:完成条件固定三件——调度器的 runs+exit、任务自己的 stdout/stderr、下游产物(文件/行数)。缺日志或 exit≠0 必须标失败。禁止用「plist 在 / 到点了 / agent 已 load」推断拉取已通。
2. **IM / Webhook / 开放平台**:权限开通与事件订阅分开验收。权限只解决「能不能调 API / 能不能看见事件名」;**没有把「接收消息」订到你的公网 URL,平台就不会推事件**。用户报「bot 没反应」时,第一步固定看服务端 access log / `wrangler tail` 有无入站事件 POST——禁止用「权限页已勾 / 审批已过」推断回调已接通。UI 事件名往往是「Receive messages / 接收消息」,不要只搜 API 字面量。
3. **一应用一事件 URL**:Lark/飞书(及多数 IM)一个应用通常只有一个请求地址。新产品面优先专用 bot + 专用 Worker URL;挂在已接编排网关的 app 上,事件会被另一消费者收走或根本不到你这边。必须共用时要在同一入口显式路由。

### C 附4:输出校验 · 空数组 fallback 不得抹掉已抽出的清单

> 源流:inbox-radar 2026-08-13 gold-set;digest llm-fallback-empty-must-not-erase-extraction。

当输出 schema 允许 empty-array fallback 时,空数组只代表「结构真的不存在」,不能因分类掉进 fallback 路径而抹掉正文已抽出的清单。分类/重路由之后仍须用确定性校验:**结构化 outstanding 非空时,禁止 LLM 摘要把状态写成「无待办」**。

### C 附5:身份 · 通讯痕迹里出现过 ≠ 可写花名册

> 源流:inbox-radar 2026-08-13;digest no-invented-directory-without-human-confirm。

从邮件/IM 痕迹推断组织目录时,**出现过的邮箱 ≠ 可写花名册**。只在人类确认后登记身份,再 regenerate 派生 actor 映射。禁止 agent 为了「分到人」而 invent roster 行——这是「不发明业务规则」在身份面上的同构。

## D 类:堵「决策幻觉」(AI 替人做产品决定)

11. **暂停项写成禁令**:用户说「以后再聊」的(加密策略/状态机),不是从计划里删掉,而是写进 AGENTS.md:「未获明确指令前不实现、不假设」。删掉=留缺口=AI 某天自作主张补上;禁令=缺口被钉死。
    ✓ 用户 7-04 问「加密进计划了吗」,一查禁令条款即答,零歧义。
12. **高幻觉区纯函数化 + 边界钉死**:时区换算、ISO 周、金额、幂等——AI 最容易「差不多先生」的地方,一律抽纯函数 + 边界单测(HK 23:59/UTC 跨日/2026-W53/双投递收敛)。安全属性(防枚举「响应逐字节相同」)写成**测试断言**而不是「注意安全」。
    ✓ B#3:模型拒绝为「下周一」编日期(没参考日期时 due_at 留 null)——好的信任边界让模型的诚实可被利用:prompt 注入今天日期后问题根治,而不是逼模型猜。

## 附:第五类——偏好缺口(2026-07-05 官网 v1 返工后增补)

前四类都在事实域(有客观对错)。第五类在**偏好域**:待拍板项被静默选边、范围靠推断、「建议未被反对」当「已同意」——错了不叫幻觉,叫「替用户做了他没做的决定」。封堵工具完全不同:追问/多变体/勾选/回显,按「偏好方差×返工成本」2×2 选用。全套见 [elicitation-protocol.md](elicitation-protocol.md);已烧进 [kit/explore-prompt-template.md](kit/explore-prompt-template.md)。

## 附:第六型——取证幻觉(2026-07-14 Euan gitleaks 事故增补)

完成幻觉的姊妹型:完成幻觉 = 谎称**做了**;取证幻觉 = 把没看见的细节补成**看见了**——工具输出里没有的 File/Line/Commit,用生态惯例与 plausibility 重建成「事实」报告。前 12 条堵的是「做」的缺口,这三条堵「查」的缺口(机制与模型档位无关,防线必须机械化,不赌模型自觉):

1. **细节缺失的标准动作 = 复跑取证**:本地复跑同版本工具、开详细模式(`-v`),绝不从记忆/生态惯例重建细节。
2. **「看过片段」≠「读过日志」**:grep/head 过滤后的视图只是片段,「没匹配到」≠「不存在」;基于片段下结论前先确认过滤器本身没坏(Euan 实证:日志行首 job 名前缀 `secrets` 让 grep 命中率 100%,过滤器失效未被察觉,「日志里没有细节」这个事实被淹没)。
3. **锚点出口前存在性检查**:报告 commit/路径/行号之前先跑 `git cat-file -e` / `ls`——让编造在出口前碎,不是在用户面前碎。
4. **命令的默认作用域 ≠ 你传的参数范围**(跨工具同族):
   - **写入/暂存范围**:`git add <路径>` 只增不减,不构成提交范围限定——commit 前读**全暂存区**(`git status --short`);验证勿只信 `git show --stat`。(Euan 2026-07-26:supabase/.temp 残留吞入 CODEOWNERS commit。)
   - **读取位置/cwd**:决定工具读哪份文件的常是 **cwd**,不是你传的 `--workdir` 类 flag。「我传了 flag」≠「工具照做了」。**不可逆动作**(config push / deploy / publish)前必须验证作用域真的生效——先跑只读命令看工具报告的实际路径,或核对将要应用的 diff **方向**。「知道两份文件不同」≠「工具会用对的那份」。(Euan 2026-07-29:`supabase config push --workdir <worktree>` 仍读主目录旧配置,把当日 site_url/白名单/配额全部冲回旧值;cd 进 worktree 再推才正确。)
5. **错误码「变好」≠ 已修复——先验因果链**:排查期间若状态码/症状改善,先问**改善与我的修复动作之间有没有因果链**;没有因果链的改善不算证据。限流(429)、熔断、降级响应会**覆盖**真实故障码——解除限流后必须复测,才能判定是否真的修复。(Euan 2026-07-29:GoTrue 500 重试触发 `over_email_send_rate_limit`→429,网关防枚举吞成 202,误判「5xx 消失=修好了」;调高邮件配额后 500 立刻重现。)
6. **交给人执行的步骤 = 最高取证标准(外化面)**:凡是**用户去外部控制台照着点**的清单(OAuth client 类型、域名、密钥勾选),每条必须有**官方文档原文**背书并就地标 `[doc]`(URL 或引用);抓不到的老实标 `[待查证]`,禁止补「看起来合理」的路径。**过时/臆测清单比没有清单更危险**——没清单人会查文档,有错清单人会照做,且常表现为无差别 401,自查成本极高。(Euan 2026-07-30:external-setup 旧版教 iOS+Android OAuth client,官方实为 web+iOS;Apple 纯原生不需 Services ID。)
7. **配置真相用 secret-safe 探针,不靠叙述反推**:迁移/审计运行配置时,写只输出布尔分类的可执行探针(协议/位置/能力);叙述文档只做线索——不得从文档反推 secret、endpoint 或当前 provider。(inbox-radar:历史说明误认 provider,探针证两路合规 HTTPS 且不打印密钥。)
8. **跨运行时契约锁可观察语义 + adversarial matrix**:不要假设 Python/Worker/URL 路径规范化「应该一样」;先写 decode→canonicalize→accept/reject 契约,再在各实现上跑同一 adversarial 输入族。
9. **不可信字段生产者+消费者双门**:会持久化并跨运行时消费的字段,producer 写入前净化,每个 consumer 仍独立 fail-closed——单边校验不够。
10. **合同测试锁不变量,不锁旧措辞**:文档/安全合同断言必需概念与禁止路径;phrase oracle 会阻止更安全的语义升级——先保留 RED 证据再改结构 oracle。
11. **竞品私有栈不可证 ≠ 阻塞本项目选型**:合法公开面挖不到的引擎/库名不得当前置阻塞;选型用可验证产品约束 + 可逆分层,公开 teardown 只作线索(hk-sfc-licensees competitor teardown §6)。
12. **工具静默降级伪装合格**:扫描类工具的 `exit 0`/末行「通过」必须连同**范围指标**(文件数/耗时/是否真 git 仓)一起读——worktree 指针 `.git` 可让 gitleaks 先 ERR 再 INF no leaks exit 0。CI 把「取工具」与「跑工具」拆 step,基建超时红 ≠ 扫出密钥。(Dartify 2026-08-02)
13. **入口校验收紧 → 夹具可达性**:改 schema/鉴权/限长后全仓扫测试夹具是否仍到达被测路径;夹具值满足新约束且明显是夹具,勿用卡边界短值。
14. **边缘身份键只信覆写头**:CF 等上限流 IP 只认 `CF-Connecting-IP`(或等价边缘覆写),取不到 fail-closed 落 unknown 桶,禁止回退可伪造 XFF。
15. **多入口同凭证字段同一 schema**:注册/登录/改密共享 password 上下界,禁止写宽读窄。
16. **「最新」是需取证的断言**:对外交付(装机/演示)禁止从本地 HEAD 推断最新;必须对表 default branch 并写出落差数字。
17. **闸拒命令字面 ≠ 用户禁止目标**:安全分类器/PreToolUse 拒的是**这条命令字符串**,不是任务目标,且可能间歇误拒。遇拒:①换**更保守**的等价手段(`reset --hard`→`ff-only merge`、去管道裸跑)②原样重试一次;两步不过再向用户要授权。**禁止**一次拒绝就缩减交付范围或改口「做不到」;也**禁止**为绕闸升级破坏性。
18. **判别式探针 vs 压力测试**:证明「某个约束真在生效」时,让被测方违反约束(压力测试)是弱证据——模型/系统可能出于别的原因恰好合规。强证据是构造一个**只有约束成立才可能出现**的可观测值(提示词从未提及的暗号字段、随机 nonce、超出训练分布的字面量),它出现即判定成立。配套第二问:把一个明知非法的约束递进去,若系统照单全收(200 不报错),说明校验不存在,下游的事后校验一条都不能撤。(Dartify 2026-08-15:json_schema 压力测试过了仍可能是「模型自己想通了」;schema 加 `schema_marker: enum["ZQX-7788"]` 原样吐出才算数。)

(Euan 全链条实证:CI 调 gitleaks 无 `-v` 只打统计行 → agent 编出「api/.dev.vars.example L7 · generic-api-key · commit 4a91c3…」全套似真细节 → `git log --all` 证实该文件全历史不存在、commit 号不存在;正确动作事后验证有效:本地开 `-v` 复跑一分钟拿到真 finding。)

## 附:开发期地板 vs 生产 API 门禁(2026-07-18 IPONews 实证)

**dev floor**(IDE SessionStart / PreToolUse / 本仓 preflight):防 **coding agent** 未读规则就 push、批跑、毁数据——装在开发者机器上。  
**prod API gate**:产品形态是「LLM → 你的 HTTP/API」(Vercel/Cloudflare Worker 等**无** Claude Code/Grok 运行时)时,防幻觉进金融/业务结论必须落在**程序层**(无 Evidence → refused、结构化字段只读 extractions、禁止裸 chat 当事实源)。

**禁止**把 hook 当生产护栏;两层互补、不互相替代。kit/claude-hooks-template 文首已钉「hook 非生产」。

## 一句话版

> **让 AI 少幻觉的方法,不是叮嘱它「别幻觉」,而是把它每一步的对错都变成可机械判定的事实:接口=同一份文件,状态=单写者台账,完成=命令输出,边界=禁令条款。缺口填完,幻觉自然没了生长的地方。**
