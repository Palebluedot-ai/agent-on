# 真相源治理:单一不够,还要层级 + 仲裁次序

> 职责边界:本篇管「一个项目里哪份文件算当前真相、冲突时听谁的、引别人的仓时怎么引」,不管具体某份文档怎么写。
> 源流:二代 communication-governance-playbook/docs/source-of-truth-map.md + 支线 evolving-memory-system/04_protocols/ve-governance-adapter-v1.md,2026-07-07 批二移植

## 一、为什么「单一真相源」这句口号不够用

大家都知道要有「单一真相源」(single source of truth)。但真到项目里,单一是个假象——文件天然分三种身份:**现在的规则、迁进来的旧材料、原始证据**。二代吃过一次亏:历史聊天里生成过一批文件,后来被迁移、重命名、归档,新仓又开始重写正式文档。于是每次都卡在同一个问题:该看哪份?imported 里的旧文件还能沿用吗?archive 的 transcript 算不算规范?

所以「单一」要拆成两件事:**层级**(每份文件属于哪一层)+ **仲裁次序**(冲突时哪层压哪层)。缺了仲裁次序,历史材料会悄悄「自动覆盖」当前规则——这是最隐蔽的漂移。铁律一句话:**历史材料不得自动覆盖当前决策。**

## 二、三层怎么在新项目落地

| 层 | 是什么 | 在 agent-on 骨架里对应 | 身份 |
|---|---|---|---|
| **Canonical(当前)** | 当前生效的规则 / 状态 / 契约 | `AGENTS.md`、`docs/`、`docs/state/progress.yaml`、`contracts/` | 唯一权威 |
| **承接(迁入)** | 从旧仓 / 旧上下文搬来的有效材料 | `docs/imported/`(或 `imported/`) | 上游证据,非工作文档 |
| **举证(原始)** | session 归档、日志、transcript、决策快照 | `docs/snapshots/`、`archive/`、`loop-notes.md` | 只负责追溯,不定规则 |

落地规则,三条:

1. **当前只认 Canonical**。产品定义、阶段状态、phase 语义,一律以 Canonical 层为准。承接层或举证层出现不同说法,**不能自动生效**。
2. **收口才算数**。旧材料要沿用,先走一步「收口」:把真正通过的内容誊进某份 Canonical 文档,并说清进的是哪一份。没收口的 imported 文件,永远只是证据,不是工作文档。
3. **判断沿用先问两句**:它进 Canonical 了吗?没进的话该进哪一份?——这两问挡住了「之前是不是聊过、文件到底在哪」的反复回潮。

## 三、仲裁次序(冲突时的硬优先级)

```
Canonical(当前)  >  承接(迁入)  >  举证(原始)
```

- **Canonical 负责当前**:说了算。
- **承接负责承接**:提供素材,不提供裁决。
- **举证负责举证**:证明聊过什么、帮找回上下文,不决定现在怎么推进。

对应到状态机(见 [phase-gates.md](phase-gates.md)),这条落成一个 block 理由码 `BLOCK_SOURCE_OF_TRUTH_CONFLICT`:承接 / 举证材料与当前 Canonical 冲突、又没先完成收口时,拒绝放行。

## 四、跨仓引用:下游只映射不复制

新项目引用另一个仓的规则(最典型:一个新项目引用 agent-on 的方法论)时,最大的坑是**把正文复制过去**——两边各改各的,规则双写漂移,最后没人知道哪份是对的。

正解是**下游只做一张薄薄的映射表,不搬正文**。支线记忆仓的 governance-adapter 已经跑通这套,照搬即可:

1. **pin 版本**:映射文件里写死主规则仓的路径 + 一个 pinned commit(例:`agent-on @ 8f175b4`)。你锚定的是那一刻的规则,不是随时会变的 HEAD。
2. **只映射不复制**:本地文件只写「本仓怎么落地这条规则」(哪些目录可写、冲突归谁),**主规则正文一个字都不抄**。想看原文,顺着 pin 去上游看。
3. **改动走显式升级**:要跟进上游新规则,只做两步——上游先改并提交;下游只更新 `pinned commit` 和必要映射。**永远不在下游改主规则正文。**
4. **跨仓写入要证据**:确需往上游仓回写(比如「agent-on 结账」把沉淀搬回)时,附一张 Promotion Card——source / evidence / confidence / review / rollback / trace 六项齐,缺则拒绝落盘。防的就是随手一改就漂移。

## 四½、仓内投影:跨仓钉了三根钉子,仓内一根都没钉

> 增补 2026-08-20。源流:本仓自举实测——一条关于 guard 行为的断言被判错(值守独立读源码复核后纠正),同期五条 lane 指着已不存在的 worktree 挂在台账上。两件事一个在文档、一个在台账,是同一个病。为什么链见 [../snapshot/2026-08-20-projection-drift.md](../snapshot/2026-08-20-projection-drift.md),案例见 [../bench/cases/43-projection-without-provenance.md](../bench/cases/43-projection-without-provenance.md)。

§四那三条管的是**跨仓**。但实测下来,判定错**全部发生在仓内**——没有人跨仓引用错,是仓内的读者读到了一份仓内的副本。

### 先把两类记录分开(这是内聚的切口)

| | 原件 | 投影 |
|---|---|---|
| 是什么 | 这里第一次产生的判断 | 别处事实的副本 |
| 例子 | 方法主张、决策理由、为什么链、案例的教训段 | 「闸拦哪些 git 操作」「这条 lane 在哪个 branch」「谁在班」 |
| 真身在哪 | 就在这里 | `cli/src/*.rs` / git / `oncall.json` |
| 会不会过期 | **不会**。当时的判断永远是当时的判断 | **会,而且没有声音**——副本不知道自己是副本 |
| 读者分得清吗 | — | **分不清**:两类写在同一份文件、同一种语气、同一个时态 |

这条区分不是新原则,是把 §二三层(canonical / 承接 / 举证)从**文件粒度**推到**句子粒度**。三层管的是「这份文件算不算数」;这里管的是「这份算数的文件里,哪几句需要复核」。一份 canonical 文件里同时躺着两类句子,是本仓最常见的形态。

### 判定错的三段式:不需要任何一份文件写错

1. **一个机器事实有 N 份投影**。本仓实测(仅 md,排除 `.git`/`target`/`legacy`/`intake`,共 139 份):`landed` 出现在 **70** 份、`owns` 47 份、`PreToolUse` 32 份,而定义各只有一处代码。
2. **投影不带回指,或只回指到文件**。
3. **读者落在任意一份上,把它当事实。**

第 2 条是要害。本仓其实**已经自发形成了回指习惯**(多份快照头部写着「机制正文在 X、实现在 Y」),但它写在散文里、指到**文件**、没有任何东西验它——而**文件路径不会因为里面的行为变了就失效**。实测:出事的那份快照确实点名了 guard 的实现文件,指针至今有效,基于它的行为断言却是错的。**指到文件的指针,不能证明任何一句关于行为的话。**

与 [multi-contributor-protocol](multi-contributor-protocol.md) §三½.6 第 4 条「转述 ≠ 出处」是同一根问题的两半:那半管**跨窗口**转述要溯源(纪律),这半管**仓内**副本要带可验的锚(机械闸)。按 [meta-principles](meta-principles.md) 第七条,没有闸的规则是纸面的——所以那条纪律必须配这条闸。

### 三根钉子(与 §四 同构,介质换成仓内)

1. **投影必须带回指,回指必须点到符号**:`<!-- src: <路径>#<符号> -->`,例如指向 guard 里那个把 commit 与 push 一起收进去的集合(<!-- src: cli/src/guard.rs#commit_push_dirs -->)。点到文件不算——文件不会烂,符号会。
2. **回指必须机械可验**:`agent-on drift` 逐条解析锚点,验文件在不在、符号还在不在;并同时对账台账侧的派生字段(幽灵 lane / branch 对不上 / base 是会动的本地分支 / base 解析不了)。
3. **只报不拦,但每行必须带 owner 与非破坏出口**。账实不符是**别人的账**;拿它拦本会话的 commit,正是[案 40](../bench/cases/40-gate-exit-unreachable.md)「出口在权限外的闸 = 死锁」那个老病,还会逼出「为了让闸变绿而改账」。默认 exit 0,`--strict` 留给 CI。

### 边界:只管机器行为断言,不管方法主张

「恒红的闸等于没有闸」是判断,不需要锚,也不会过期;「闸对 landed 轨不设防」是机器行为,必须锚。两类混在同一份文件里没问题(自包含仍然优先于去重),但**关于机器的那一句必须带锚**。

**豁免面写死**(豁免不是漏,是内聚):`intake/`(承接层原始素材,照抄别人的现场话)、`legacy/`(归档证据)、`CHANGELOG.md`(历史记录,不声称「现在是这样」)。这三类本来就不主张「当前如此」,给它们上锚是噪音。

### 同一个模式,别的介质也适用

台账(lane / oncall)、人读状态面(dashboard)、案例集,都是投影。§五½的喂养表只要求给**人读状态面**登记「谁喂 / 何时喂 / 什么闸 / 漏喂怎么发现」——**同样的四问对台账与规则从来没问过**。识别器:**一条规矩只应用在 N 个同类介质里的 1 个,比没有这条规矩更容易骗人**,因为它让人以为这个问题已经管过了。

## 五、单读面:给人读的状态面,一个受众只养一份

单写者管「谁写」,这条管「几份」。给人读的状态/待办面(dashboard、真相之页、action list)一个受众只养一份、放显眼处(项目根目录);同受众同类信息面的**第二份自诞生即漂移倒计时**——一律直接删(含指针页),活引用当场改齐,历史存档不改也不救。新开任何人读面之前先答一句「谁在每次变更时喂它」,答不上 = 不开。(Euan 实证:ACTION-LIST 与真相之页并存 6 天即彻底过期,被用户抓包)

### 五½、喂养表:谁喂 / 何时喂 / 什么闸

> 源流:Euan 2026-07-30 harness 审计——dashboard 停 07-27(生产域仍写旧 api.euan.pro、等你区已办完的 CF 项仍催、语音 0% 而 PR #18 已上);AGENT-HANDOFF 分工快照 4 天过期。digest truth-surface-feeding-table。

每张状态面(人读或机器读)开面时登记**四元组**,缺一不开新面:

| 面 | 唯一写者 | 喂养时机 | 机械闸 | **漏喂怎么发现** |
|---|---|---|---|---|
| 例:dashboard.html | orchestrator | 合流必更 / 口令「更新仪表盘」 | 握手核 mtime vs progress | handshake 标红 / PR checklist 勾状态面 |
| 例:progress.yaml | orchestrator | 阶段切换 / 合流 | 单写者 | CI 或 merge 核对 phase status vs 已合 PR |
| 例:TODOS 推迟项 | 认领人 | 触发命中时 | **禁「下次顺手」** | 触发须=机械信号(路径∩改动)或日历死线;CI/对账脚本扫过期触发 |

**无人喂养的面比没有面更危险**——按错误信息源处理:当场从真相源重绘,或声明存档/删除,不许放着继续误导决策。

**推迟项触发纪律**(Dartify 2026-08-02:一次对账 10 条「下次顺手」已命中未回表):写成「下次动 X 时顺手」= **没有闸**,必然静默过期。要么绑可机械检查的信号,要么写日历死线。真相面同理:只登记「谁喂」不够——**漏喂必须可发现**。

### 五¾、易变事实 / 幽灵 backlog / 历史隔离(inbox-radar 2026-07-31)

1. **计划状态随证据收口**:阶段计划/TODO 表必须随验收证据同步;历史问题可保留原貌,但**当前状态**只能写可验证事实并指向唯一权威状态源(progress/phase)。否则旧 TODO 反复抬成「幽灵 P0」。
2. **长期状态文件不 self-pin live HEAD**:不把「当前 main 是某 SHA / ahead N / 最新 CI」写成持久真相——下一次 status commit 立刻打碎。具名历史观测可记(对象+时间+命令);易变计数只在**动作前** fresh 查询。
3. **被替代文档显式隔离**:旧规则/roster/说明标 `history`/`disabled` 并从当前生成链退出;若保留作证据,加 drift test 防它再被当成现行真相。
4. **代码与状态面同批收口**:exact HEAD + 测试证据 + 所有 canonical 状态面(progress/phase/dashboard)同批核对;代码前进而状态面未落盘 = 环节未收口。

## 六、宪法暂停项的局部解禁

Canonical 里「未获指令前禁止」的暂停项允许**局部解禁**,但必须:

1. **D 表划界**:决策记录写清「本次已拍什么 / 仍禁什么」(例:原图 opt-in 已解,真·E2E/KMS 仍禁)。
2. **多面同步**:同批更新 AGENTS 暂停表述、人读仪表盘、TODOS 落地项、威胁模型相关句——禁止只改业务 docs。
3. **禁止聊天默示全解**:会话口头同意 ≠ 整栈能力解禁;执行会话只认文件层划界。

(Euan 2026-07-19 加密暂停项 → D18 局部解禁实证。)

一句话带走:**单一真相源是目标,层级 + 仲裁次序 + pin 映射是让它真的成立的三根钉子;第四根是出处锚——只要一个事实在仓里有第二份副本,那份副本就得说得出自己抄的是谁,并且这句话要能被机器验。**
