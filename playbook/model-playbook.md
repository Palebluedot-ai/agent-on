# 模型与辅助强度：按任务表现选择

> 职责边界：本篇管如何选执行器与调整辅助强度；不绑定模型品牌，不定义模型权限，不做过时型号的能力排名。派工接线见 [巡逻执行书](../kit/patrol-control-plane.md)。

## 核心

角色、模型和宿主分开。规划、执行、验收所用的执行工具、模型与推理档位由用户决定，Agent-On 只按用户明确指令调度和编排，不拥有自动选型或改派权。入口负责目标与共享改动，值守负责合并；登录、额度、支持模型与实际权限由各自宿主执行。

没有指定型号就沿用宿主当次设置，不要求用户先填模型、不根据目录推荐追加覆盖。用户显式选择原样保留；拒绝、限流或能力缺口不授权自动换模型、降档、切工具或重放任务，只保留结果与原因供用户决定。对相关任务出现可重复的能力缺口，可提出针对性的约束、例子或检查建议；表现稳定就撤掉辅助。不能用几题分数声称获得普遍可靠性，也不为换型号先跑一小时考试。

## 哪些辅助仍有用

- 长任务需要续接：默认原窗口原生 compact，复用当前任务文件保存目标、已拍决定、未完项和证据；出现持续偏离才考虑新会话。完整约定见 [会话续接](../boot/session-handshake.md)。
- 共享文件会互相撞：统一归属，先共享任务再消费者；路径扫描只提示候选风险。
- 行为容易回归：针对行为固定测试；视觉变化用预览、交互与用户反馈。
- 判断不可靠：对高风险结论独立复算；普通任务不按模型品牌额外加一整套审查。
- 外部环境会变：读取真实载荷或接口文档；未执行的验证保留缺口，不能报通过。

## 选择执行器

用户指定现成 host 就复用。用户授权跨模型意见时，明确一个问题与输入，记录真实返回和来源；没有安装/登录时说明缺口，不代装工具、降权限或换工具。可以按用户已明确的阶段顺序和指派交接，但不能把「允许编排」读成「允许决定用谁」。

`dispatch --host claude|codex|grok --model <宿主支持的id>` 是可选薄适配，默认模型参数留空。只读分析共享项目，写任务按需要隔离；不用每页新树来“体现并行”。

阶段交接分清**结果、确认、派工**：只读规划的报告先作为数据回传，Stop 或“已完成”不授下一阶段执行权。用户明确确认这版结果并指定执行者后，入口才把精确结果与时间、目标、范围和证据带入下一任务；来源更新不能偷偷替换用户确认版本。交接不验收或释放上游，不让报告扩张目标或模型权限；代码成果的下游仍等真实合入。薄接线见巡逻执行书「确认规划后的单次阶段交接」，不建通用工作流引擎。

比较成本看同类实际任务的返工、耗时、有效验证和费用。没有运行数据就写未测。公开参数、旧项目经验和通用价格标签不能代替本项目效果。
