# 工作流编排:确定性扇出的防幻觉七件

> 职责边界:本篇管「一次派出一群子代理(读 / 分析 / 各写各的文件)时,怎么让任务确定性跑完、且幻觉无法存活」;多 agent 改同一代码库的并行走六步协议(kit/AGENTS-skeleton.md §10),分工见 §〇。
> 源流:agent-on 自身融合工程实战(2026-07-07~08:三镜头设计评审 + 17 案例扇出 + 限流断点续跑,单日 22 代理),批四后消化落盘。原则工具无关——Claude Code 的 Workflow 工具是当前最顺手的载体,Codex 语境下见 §三。

## 〇、先分清用哪个:会不会撞文件?

- **会撞**(子任务改同一代码库、彼此有接口)→ **六步协议**:契约先冻、轨道 = worktree 物理隔离、契约测试当裁判
- **不会撞**(读 / 分析 / 各写各的文件,互不相交)→ **本篇工作流扇出**:不需要 worktree,需要下面七件

**大扇出前,探针先行(闸门)**:先派 1 个探针子代理,把本次扇出依赖的关键工具(调研类 = WebSearch 与 WebFetch)各实跑一次;探针不过,改主会话定向抓取,**不启动 fan-out**——环境性故障对每个子代理都成立,扇出只是把同一次失败乘以 N。(IPONews 同机正反对照:无探针 22 代理/18 错/66 万 token 零产出;有探针 105 代理/0 错。案例 24)

## 一、七件(每件一句为什么 + 本仓实战证据)

1. **控制流写成脚本,不靠模型记忆**。扇出几个代理、哪里设 barrier、谁先谁后,由确定性脚本决定——「忘了做某步」在结构上不可能;barrier 只设在真需要全量结果的点(评审必须等三案齐),其余全并行。
2. **返回必须过 schema**。子代理的交付强制为通过 JSON Schema 校验的结构化对象,不合格自动重试——想发散都没有语法空间。(实战:三提案 / 对抗评审 / 17 案例回执全部 schema 强制,零格式漂移。)
3. **任务书自包含 + 禁区显性**。源料精确路径、评估尺子、风格契约、返回格式、不许碰什么,一次给全;「只写点名文件、不跑 git」写进任务书——负空间不写,代理就替你决定。**流水线中间产物是导航不是真相**:下游 implementer 消费上游审计/摘要/spec-digest 时,任务书显式写「读源不读摘要,摘要错了就地勘误回写」——把中间产物当权威会把上游的错原样实现。(Euan 实证:动效审计摘要两处错挂时长/scale,implementer 逐行读 demo 一手源才发现,029e5ab/9523ddc。)
4. **证据强制进任务书**。涉及可执行物,派工时就要求实跑并贴原始输出——「应该没问题」在任务书里判死刑。(实战:schema 轨贴了 4 个 JSON 校验 OK + 两次 lint 的 exit code。)
5. **对抗验证做成独立 stage**。产出后必接「假定有错,找到它」的审查代理,审查者与产出者绝不同一实例。(实战拦截:代际标错 9 处、audit-lint null bug、5 卡虚指一个不存在的清单、结账执行书对 S 档空转——没有一个是「大概没问题」混过去的。)
6. **失败语义显性 + 断点续跑**。代理死掉(限流 / 超时)返回空值、被过滤,不产生「我记得做过了」;重跑时已完成的走日志缓存、失败的重来;要强制重审的,改一行审查 prompt 击穿缓存。(实战:11 个案例代理被限流打死,resume 后成功者走缓存、失败者重跑、审查 prompt 加一行触发全量复审。)撞模型配额上限的续跑变体:已完成代理的成果照用不重跑,缺口部分改派降档模型(sonnet/haiku)子代理续跑,合成与判断留在主会话主模型——机械 fetch 类本就该降档(§二)。(IPONews 单会话实证:12/14 撞限,4 个降档代理零返工补齐。)

   **熄火续跑操作序**(session limit / 模型额度 / 会话上限中途死):① 先看工作树是否干净——熄火代理常留半成品,移到 scratchpad 保清白再续;② 用 `resumeFromRunId`(或等价)原地续跑,同 (prompt,opts) 已成功卡走缓存、只重跑死的和新增的;③ **禁止整轮重发**(浪费 token + 重做已落地的卡)。Euan 三轮 resume 实证 wf_af662187 / wf_c87e14a2 / wf_e46ee655。
7. **单一合流权**。代理只交付、不落地;orchestrator 逐件审查后分层 commit,每个 commit 可独立回滚——幻觉即使活过前六件,也进不了主干。

## 二、混编旋钮(与 model-playbook 联动)

- 执行型代理(读析写单件)配低档 effort / 便宜模型;**评审席升档**——对抗的持续性值钱
- 判断(合成、裁决、合流)永远留在 orchestrator 自己脑子里,不下放给任何子代理

## 二½、同 worktree 并行 implementer:文件域互斥 + 共享文件 owner

> 与 §〇「会撞 → 六步协议 / worktree 物理隔离」互补:有时同 worktree 派多个 implementer(各写互不重叠文件)是合理的。此时**文件域划界**必须在派工时显式写死。

1. **互斥文件域**:每张 implementer 卡列「只许改的路径前缀」;相交 → 拆卡或改走 worktree 六步。
2. **共享文件必须指派唯一 owner**:契约表 / 索引 / 清单 / barrel export 等跨切片共享面,要么派唯一 owner 改,要么明写「留收口人补」——**禁止**「各补一行」却不点名谁补。
3. **回避是对的,漏派才是错**:每个并行体理性回避共享文件(防撞车)→ 卡上共享条款集体落空。Euan 实证 wf_72f612c3:三 implementer 同 worktree TDD 零互踩,但 `api-contract.md 各补一行` 三人皆回避,收口人补行(ca2e025)。

落地:kit/phase-card-template §2「共享文件 owner」行;与 multi-contributor §二.2 三共享面归口同构。

## 三、穷尽式提取模式(「每个 X 都要留存/核对」类任务)

分片并行提取 → 合并 → **双路对抗核对** → 定稿。核对是命门:核对者必须**独立生成机械对表清单**(如从源码 grep 出全量状态名)再逐项对表,不许复读提取结果——复读式核对连提取者的漏项一起继承。(Euan 实证:9 代理提取 558 行状态清单,双路核对抓出 7 处勘误,含「渲染层覆盖死代码」「有逻辑无 UI 的隐藏能力」这类单路必漏项。)

## 三¼、大单文件规格:并行深读 → 差距矩阵先入仓

> 适用:数百 KB 的单文件 demo / 巨型 spec,规划前必须「读透」又读不进单上下文。

编排骨架:

1. **按结构行域切段**给并行 readers(每段结构化 schema 收口,不自由散文)
2. **另派现状盘点** agents(代码 / API / schema 面,与 demo 段读者正交)
3. **末位一个综合 agent**对撞出「逐屏(逐模块)差距矩阵」
4. **矩阵先入仓**,规划 / 契约 / phase 卡全部**引用矩阵**而非重读原文——盘点一次,消费多次

Euan 实证 wf_8f5a3d86:10 agent 深读 474KB demo → 28 屏差距矩阵 + 后端缺口 20 条入仓,后续契约与 phase 卡直接引用。

与 §三关系:§三是「穷尽留存」;本节是「规格→现状差距」的施工口径生产。

## 三½、外部事实直核纪律(价格 / 榜单 / 供应商阵容类,与 §三同族)

1. **证据必须来自浏览器渲染后的 DOM**:WebFetch 摘要与纯文本抓取会静默漏掉 JS 渲染内容(tab 组件、动态表格),还可能谎称「页面上没有」;表格类必须核对总行数——默认视区只渲染前 N 行,榜上有名的会被静默截断。(IPONews 单会话 4 站点实证:OpenAI 摘要漏价、Gemini/Cohere tab 藏价、FinMTEB 表格第 9 名被截。)
2. **型号与价格必须当日直核 + 逐项标查证日期**:LLM 供应商阵容/定价的训练记忆必过期——涉及选型/成本的结论,所有型号名与价格当日官方页直核,每项标注查证日期;prompt 里预填的型号名只当检索线索,不当事实写进结论。(IPONews 同日 6 家直核,5 家与「常识认知」不符:旧型号退役、新系列上位、许可条款变更。)

## 四、边界与诚实

- 七件防的是「幻觉存活」,不是「幻觉产生」——模型仍会编,但编出来的过不了 schema、贴不出证据、活不过对抗审查、进不了主干
- Workflow 工具是 Claude Code 的能力;Codex 语境下第 1、6 件退化为手工纪律(编排步骤写成 checklist 逐项打勾、失败手工登记后重派),其余五件原样成立
- **扇出写作有代价**:需要统一作者声音的长文(README、宪章、合成裁决)不要扇出——素材可以扇出去收,成稿必须单脑
- 与防幻觉十二机制(anti-hallucination.md)的关系:十二机制是项目开发全程的通用封堵,本篇是「多代理扇出」这个特定场景的专用装备,同一个公式(幻觉 = 缺口 × 自由度)的两次应用
