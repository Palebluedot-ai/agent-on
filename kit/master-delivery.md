# 交付统筹：分工、跟进、合入

> 职责边界：`agent-on master` 的项目接入与执行约定。复用值守身份、landing 队列和独立合并审计；宿主会话负责需求、分工、修复与唤醒。它不新建模型运行时，不自动开窗口。

## 日常入口

用户说“agent-on 交付 / 统筹这个目标”后，沿 [交付入口](delivery-workflow.md) 续接目标、归并共享修改、按需要派工。原窗口读取 `agent-on status`，无需维护 Dashboard。单个窗口够用时直接实现。

一批成果就绪后，由已获授权的值守或无人在班时的维护者运行：

```sh
agent-on master                 # 共读开放 PR、等待项、修复项和可合项
agent-on master --apply         # 执行本轮已授权合入，默认最多 10 条
agent-on master --apply --pr 42 # 限定这一单
```

命令逐条处理可合入的 PR；合完刷新目标分支与依赖再选下一条。一条 CI 运行中的 PR 不挡其他就绪项。已有值守在班时，其他窗口可以查看，执行仍归原值守。没有 lane 登记也能交付；损坏 lane 和旧缓存作为诊断，不阻止读取真实 PR。

收到 HOLD 或需求重新打开时，把对应 PR 保持 draft 或挂 `hold` / `do-not-merge` 标签，恢复 READY 后才撤销；暂停不能只留在一段聊天里。master 从 PR 的持久状态读取暂停，CI 全绿也不合。

## 状态决定下一步

| 状态 | 谁继续、做什么 |
|---|---|
| READY | 当前证据与政策允许；`--apply` 核最新 head 后合入并记账 |
| WAIT | CI / 必需评审 / 平台状态未就绪，宿主下轮重读；不请用户反复确认 |
| FIX | 有具体失败，主会话按已有授权处理或转给作者；复查修复影响范围 |
| HARD_STOP | 命中项目政策的例外；先检查已有用户批准是否覆盖这项，再决定是否提问 |
| MERGED | 已从 GitHub 确认合入并写审计账；不是仅发送了合入请求 |
| UNAVAILABLE | 取证、身份或审计无法完成；保留诊断与未完成回执，不冒称通过 |

提交追平后，核新的 head 与它的必需检查。固定 `gh run watch <id>` 只观察那个 run，不会自动切换到新提交。master 使用 `--match-head-commit`，不使用 `--admin`、自动删分支或本地替作者 checkout/commit。服务器尚未确认合入时留待下轮，不能先记“已合”。

## 接入已有项目

1. 按 [值守接入](babysit/SETUP.md) 配好当前项目的 `tools/merge-audit/policy.json` 与审计工具；保留项目已有授权与受信作者。`repo` 必须匹配实际仓库，不能借用 Agent-On 本仓的许可。
2. `merge_method` 指定 `squash` / `merge` / `rebase`。`merge_health.required_checks` 写实际必须出现的检查名，防止新提交的检查尚未启动就误认全绿。`advisory_check_names` 只列已决定不阻塞的检查，必需名优先；未知检查仍按原政策判。
3. 先用预览核状态和政策；授权已齐就直接执行，不再重复问同一个授权。更新 CI 时同时核分支保护；已有 required 检查未改变前仍需满足。全面回归按项目需要放到夜间，架构与规则复盘可每周一次。
4. 周期值守复用宿主原有调度，每次只调用一轮；无可行动变化时安静。CLI 本身不安装后台服务、不创建定时器。未配置调度或未收到首次真实运行回执，不报“已在无人值守”。

本轮用户明确批准过的硬停范围，用实际批准证据绑定**这一 PR 的这一提交**，无需再索取一遍：

```sh
agent-on master --apply --pr 42 --head <已核完整SHA> --approval <已有用户批准记录.md>
```

记录必须来自真实用户指令，说明批准范围，并已随授权批次进入 Git；账本保存仓内相对指针以便换工作区后复核。路径存在不证明用户同意；执行会话负责核原文。禁止把作者自述、过期批准或“用户应该会同意”写成证据。PR head 变化后重新核授权覆盖范围和相关验证。

## 中断与恢复

同仓仅一个 master 执行进程可写，锁随进程退出自动释放。合入前原子保存一份临时回执；合入后记入已有主 worktree 的 `ledger/merge-audit.jsonl`，随后清除临时回执。若在两步之间中断，下次先向 GitHub 核实际结果：已合且 head 一致只补账，未合继续重新检查。不新增第二份长期账本。

独立 `report` 仍是合入前条件；链断或真实越界必须处理。正常 WAIT 不是审计事故。工作目录、任务 result、旧网页或模型自述都不能替代真实合入证据。
