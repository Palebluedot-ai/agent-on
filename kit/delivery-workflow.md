# 当前对话交付：把目标推进到可验收成果

> 职责边界：供 `/agent-on deliver`、`$agent-on deliver` 或中文“agent-on 交付”执行。检查节奏见 [功能交付](../playbook/delivery.md)。复用现有项目记录与宿主能力，不创建派工运行时、活动台账或面板。

## 1. 接住目标

读取用户目标、项目规则、已有任务和实际修改，保护未提交工作。必要时运行 `agent-on status --json`：schema v2 只提供当前 checkout 的 Git 事实、项目记录位置、值守与已有 PR 快照；goal/progress 为 null 表示无法从 Git 推断，不表示没有目标。

沿当前对话与项目已有记录确定本批结果、范围、依赖和验收。没有 lock 不自动初始化；用户要求正式接入才走 init/adopt。已有授权能够回答的问题自行处理，只问会改变结果且无法推断的决策。

## 2. 当前对话推进

默认直接完成当前目标。共享接口、路由、全局样式和锁文件先归并。确有独立并行任务且用户已指派时使用宿主原生能力，按需隔离 worktree；值守在班仍经既有路由。Agent-On 不自动建聊、启动模型、登记 task 或采集每次工具活动。

依赖必须用实际文件、提交或合入证据确认。项目原有任务文件继续作为记录，不要求复制到另一套格式。交接可以使用 [任务说明模板](track-prompt-template.md)，无需启动器。

## 3. 验证当前批次

开发中只验证受影响行为；可交付时一次需求／项目约定审查，修复后复查受影响范围。Matt、GStack、kit 同一阶段只用一套，未安装插件也可继续。

CI 区分触发延迟、runner 等待、检查执行和合入条件等待。对当前候选的必需检查失败、取消、未上报不能视为成功；未知影响范围扩大回归。文档不编译无关代码，检查名保持稳定，不用整个 required workflow 的路径跳过制造永久 Pending。本仓 Actions 每日／按需手动全量，PR、push、tag 不触发；本地按范围验证，普通 tag 不强制重跑全量，高风险或证据不足才补跑。其他项目仍认各自政策。每日健康只认最近真实完成证据；维护者发现代码回归先修复，暂停受影响发布，不宣称机器已有跨 run 自动停合入。

## 4. 交付与收口

引用实际测试输出、提交与需求依据，分别报告实现、验证、合入、发布、安装。结果回报或宿主退出不等于通过验收。

按 [合流检查](merge-checklist.md) 核相关条件。在班值守按 [交单约定](babysit/CONTRIBUTING-CLAUSE.md) 接单；无人值守时维护者沿项目已有授权交付，不强制再开窗口。需要机器统筹时按 [master 执行书](master-delivery.md) 核当前提交、串行合入与独立记账。WAIT 不拦其他就绪项，中断先核真实合入再补账。

更新项目实际使用的状态记录。普通成功不强加复盘；返工、误拦或重复劳动有证据时回流。旧派工、面板与采集用户先按 [迁移说明](../docs/migration-v0.30.md) 退场。
