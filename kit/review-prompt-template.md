# 批次审查 Prompt 模板

> 职责边界：审查一个可交付批次；按影响选择复核，阻塞缺陷与可选建议分开。检查节奏见 [功能交付](../playbook/delivery.md)。普通改动不强制另开审查窗口；高风险独立审计才要求与实现者不同实例。
> 来源：S2 审查抓到重写时误删并发测试；2026-10-25 用户反馈检查与复审阻塞交付，结合 Matt 两轴审查改为按范围复核。证据可独立核验，正常审查允许没有发现。
> 源流：Gen-1 的有效部分是带位置、证据与修正方向的反馈。当前按实际影响分阻塞缺陷与非阻塞建议，旧模板将 Minor 混入 failed 的做法退出。历史见 `legacy/gen1-role-model/` 与 `snapshot/2026-08-19-gen1-role-model-audit.md`。

```
你审查 [项目名 / 可交付批次]，基线 [commit/ref] → 当前候选 [commit]。
当前需求及变更来源：[现有任务/对话/规格位置]。
检查范围：[本批受影响行为与关键约定]；已有验证证据：[提交、环境、命令及输出位置]。
以当前已确认需求为准。需求已变更时使用更新后的验收，不用旧假设拦新实现。

## 两轴复核
1. 需求：本批可观察行为是否完成，是否有遗漏、错误或超范围实现。
2. 约定：与本次变化相关的项目约束、权限、数据与共享契约是否满足。
工具已经覆盖的格式/类型检查引用可信结果，不再手工复审。关键行为证据缺失、可疑、
已失效或需要独立对抗验证时，运行能回答问题的检查；不默认重跑整个仓库。
涉及删测时核对原行为是否仍覆盖；涉及安全或约束时核对实际拒绝路径，不能只看测试名。

## 裁决与收尾
第一行给 passed / failed / unverified 与一句话结论。

- passed：本批相关复核通过，列实际验证及复用证据；可以附非阻塞建议。
- failed：有已证实的阻塞缺陷；每条给行为影响、位置、证据、修正方向和负责人。
  Critical=当前安全/数据或关键保护失效；Major=当前验收或必需约定未达。
- unverified：缺少哪一项必需证据、由谁补齐；无法取证不是已发现缺陷，也不是通过。
- 非阻塞建议单列：风格、可选重构和范围外改进，不因建议存在而 failed 或 changes-requested。
- 修复后只复查修复点和受影响部分；没有新变化或新证据，不从头再审已通过部分。
  证据的相关提交、输入或环境变化后补跑；没有真实阻塞就结束本轮。

如实标明没有取到的证据；引用可定位到实际提交/文件/输出。判断“不存在”时说明搜索范围，
必要时用正对照验证搜索方式。实现者声明只作线索，不把未知补写成事实。
```

## 合规 / harness 审计变体(规则 vs 执行)

> 源流:Euan 2026-07-30 harness 审计 wf_2a0aa710——5 维取证 + 对抗复核 REFUTED 两处错误归因。digest audit-with-adversarial-verifiers。

对「规则写了什么 vs 实际执行了什么」类审计,**指控与定罪分离**:

1. **取证层**:代理产出指控(附命令输出/计数/链接),事实与**归因**分栏写——「发生了什么」与「为什么/谁的责任」分开。
2. **对抗复核层**:每条 Critical/High 另派**独立**代理——自己重跑命令、**以推翻为目标**;裁决三态 `CONFIRMED` / `PARTIAL` / `REFUTED`。
3. **只让 CONFIRMED(及有条件的 PARTIAL)进检讨报告**;REFUTED 的错误归因拦在门外(实证:「PR #19 单方面改验收锚」实为用户参与拍板;「CODEOWNERS 路径失效导致某 commit」实为直推使 CODEOWNERS 本就无效)。

单层审计把指控直接写进报告 = **把叙事当证据**。本变体专用于有具体风险的合规/多周回看审计，不是每个开发任务的前置流程。

- [ ] **扫描结论范围**:gitleaks 等是否带范围指标(耗时/文件数)?exit 0 是否可能静默空跑?
