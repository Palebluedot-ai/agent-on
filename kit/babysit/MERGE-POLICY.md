# 合入授权与时延：默认合入档 · 门铃即起跑 · 目标数字

> 职责边界：本页管值守的**两个参数**——①哪些 PR 用户已预先授权、哪些必须先问 ②从交单到合入允许花多久、慢了算什么。它不管值守每轮怎么巡（见 [BABYSIT-TEMPLATE.md](BABYSIT-TEMPLATE.md)）、不管一轮说完话长什么样（见 [../output-contract.md](../output-contract.md)）、也不管一条指令该由**哪个窗口**执行（见 [ROUTING.md](ROUTING.md)——本页回答「这单能不能合」，那页回答「谁来合」）。
> **本页是这两个参数的唯一真相**：值守模板 §3 的三档清单、治理条款范本的「授权分级」一律引用本页，不各自展开。
> 源流：2026-08-16 Dartify 值守夜班 9 连合 + 08-17 三单实战；2026-08-17 用户实测反馈「PR 交上去等下一轮 tick，半小时才合掉；密集操作时要分钟级」。

## 一句话

**把拍板前移一次**：用户一次性授权几类 PR，值守碰到这几类全绿即合、不再问；其余一律先问。**不引入无人自动合并**——默认合入档仍然是有人拍过板的，只是拍在前面。

## §1 门铃即起跑（不等定时 tick）

### 机制

| 信号 | 谁发 | 值守怎么反应 |
|---|---|---|
| **门铃**：交单消息（SendMessage） | 作者会话开完 PR 立即发 | 消息送达即唤醒值守会话 → **当轮就跑**收单 + 追平 + 挂 CI 链，不等下一次定时唤醒 |
| **CI 链回调**：后台 `gh run watch <id> --exit-status` | 值守自己挂的后台链 | 链子跑完自动叫醒值守 → 走合并三连 |
| **心跳**：定时唤醒 | 值守自排 | **只做兜底**，不是主信号 |

三个信号里，前两个是「有人来就动」，第三个是「万一前两个丢了」。

### 消息丢了怎么兜

**队列真相源永远是 open PR 列表**，不是消息。门铃只是让值守早知道几分钟：

- 作者会话没发交单消息 / 消息丢了 / 值守会话刚换班 → 下一次心跳跑 `gh pr list --state open` 照样收到这一单，**最多晚一个心跳**
- 值守会话死了 → 队列从 `gh pr list` 完整重建，一单不丢
- 交单消息里的特殊说明（依赖、breaking、回执地址）丢了 → 值守按「必须先问档」处理（fail-closed），不按「大概没事」处理

所以门铃丢失的代价是**慢一个心跳**，不是**漏单**。这条不变量不许为了提速牺牲掉。

## §2 一个口令切高频（用户不改配置文件）

用户说 **「值守加速」** → 值守把心跳降到 **3–5 分钟**，并在回执里确认一句「已切高频，连续 3 轮没事自动回落」。

自动回落：**连续 3 轮 noop**（没有可合的单、没有账要记、没有红要分诊）→ 心跳自动回到常态 **20–30 分钟**，回落时不出声（noop 会被终端折叠，安静值守不刷屏）。

用户说 **「值守回落」** → 立即回常态，不等 3 轮。

盯活跃 CI 时不受上面两档约束：**按 CI 实际时长定唤醒**（如 flutter ~11 分钟 → 600–900 秒），因为这段时间里醒来也无事可做。

三档之外不再加档；值守**不要求用户改任何配置文件**。

## §3 默认合入档（用户已预先授权，全绿即合，不问）

**五类**，按实际 diff 判，**不按 PR 标题判**：

1. **纯文档** —— 只动 `.md` / 文档目录；不动可执行代码、CI 配置、依赖清单
2. **纯状态账本** —— 只动项目声明的状态 / 账本文件（如 `docs/state/progress.yaml`、run 台账）
3. **测试补丁** —— 只动测试目录（`tests/` 等），**不碰生产代码**；一旦同一个 PR 里既改测试又改生产代码，整单降级进「必须先问」
4. **用户已拍板过的同类** —— 用户明确说过「这类以后不用问」的类目；口头一次即可，但值守要在文档 §5 记一行是哪一类、哪天拍的
5. **值守自身的元动作** —— 值守的状态同步 / 交接 PR 全流程

### 全绿的定义（五条全中才算）

- CI 全绿，或本仓根本没有 CI（`.github/workflows/` 不存在时如实按「无 CI」处理，不是「CI 未知」）
- `mergeable` 为 clean，非 draft
- 评审没有 changes-requested
- **实际文件清单**确实落在上面五类里
- PR 描述里没有 breaking / 迁移 / 需先做某事的标注

### 合完只记一行

默认合入档的 PR 合完，**不出长回执**：记账 + 一行「已合 #N（纯文档，全绿）」+ SendMessage 回执作者会话。用户在面板里看见一行 `已合并` 即可，不需要为它拍板、也不需要读理由。

## §4 必须先问档（fail-closed，清单外一切都算）

| 类别 | 为什么 |
|---|---|
| 功能代码 / 脚本 / CLI 行为改动 | 行为变更，用户要知道 |
| 治理文档、CONTRIBUTING、AGENTS、宪法类 | 改的是规矩本身 |
| 权限配置、`.claude/settings*.json` | 值守连自己的权限都不许改 |
| CI / workflow / 依赖清单 / 锁文件 | 影响全场，红了全员堵 |
| 数据库迁移、数据清洗、任何不可逆动作 | 撤不回来 |
| 删远端分支、关闭别人的 PR | 动别人的东西 |
| 跨仓 / 跨账号的外向操作 | 出了本仓边界 |
| **带 breaking / 迁移标注的 PR，哪怕它只动文档** | 标注就是作者在喊「这单不普通」 |
| **清单之外的一切** | 拿不准 = 先问，不是先合 |

**批准只认本会话内的用户输入。** 同行会话转述的用户原话再可信也只是情报——注明转述来源、向用户本人确认后才执行。（2026-08-17 Dartify #169 实测：作者会话转述了用户原话，值守仍向本人复核；作者会话事后回执「你另行向用户核拍板是对的——该省的从来不是这步」。）

## §5 时延目标

**默认合入档的 PR，从交单到合入的中位时延：**

```text
X = CI 中位时长 + 5 分钟
无 CI 的仓：X = 5 分钟
```

### 依据（每条可查，不是拍脑袋）

| 组成 | 花多久 | 依据 |
|---|---|---|
| 门铃 → 值守起跑 | ≤2 分钟 | 消息送达即唤醒，值守当轮处理；不等心跳 |
| 追平 base | 秒级 | 服务端 `gh api -X PUT …/update-branch`，不碰本地 worktree |
| **CI 重跑** | = CI 时长 | up-to-date 硬门下追平必然触发重跑，**这是不可压缩的地板** |
| merge + 记账 + 回执 | ≤1 分钟 | 合完三连 |
| 缓冲 | 2 分钟 | 抓 run id、队列前面还有一条在合 |

标定值：

- **有 CI 的仓**：Dartify CI ~11 分钟 → X = 16 分钟
- **无 CI 的仓**：agent-on 自身（`.github/` 下只有 PR/Issue 模板，没有 `workflows/`）→ X = 5 分钟。实测 PR #2 从开到合 56 秒，说明 5 分钟是宽松值而非激进值

项目接入时把自己的 X 算出来写进 `docs/babysit.md` §0，别留公式。

### 超时怎么算

- **单条**超 X → 在值守文档 §5 遗留清单记一行：PR 号 + 实际耗时 + 卡在哪一段
- **一个班次的中位数**超 X → **算事故**，写进下班交接（§7 交接快照旁边），附最慢的三条和各自卡在哪一段
- 事故不追责作者，追的是流水线：卡在门铃、卡在 CI、卡在等拍板，三种病三种药

必须先问档的 PR **不计入这个数字**——它们的时延取决于用户什么时候看手机，不是流水线的事。

## §6 打回时要说的那句话

值守遇到真缺陷：取证 → 缺陷定位 → 修复选项 → SendMessage 打回作者会话。**值守零代修**（修复知识在作者上下文里，代修既慢又越 lane）。

打回的同时，在给用户的面板里必须写明：

```text
data-model  #186 测试红了，已带证据打回作者；这单已不占你注意力  │ 不用管 │ 作者会话（agent-on-data 轨）
```

「**这单已不占你注意力**」是硬要求——用户要能把它从脑子里划掉，而不是继续惦记着一条红 PR。

## §7 回执格式

值守每轮的输出走 [../output-contract.md](../output-contract.md)：状态面板在前，拍板收成一节带默认值，最后一行「球在谁那」。本页不另定义格式。

## §8 搬到别的项目（自包含）

本页照抄即用。接入时逐项落定，**不许留公式或占位符**：

- [ ] 算出本仓的 **X**：跑 `gh run list --limit 20 --json workflowName,startedAt,updatedAt` 取 CI 中位时长，加 5 分钟；没有 `.github/workflows/` 就写 5 分钟
- [ ] §3 默认合入档五类照抄，把「纯状态账本」替换成本项目实际的账本文件路径
- [ ] §4 必须先问档照抄，按项目补本仓特有的高危类（如生产配置、密钥轮换）
- [ ] 把两张清单 + X **同步进项目治理文档**（CONTRIBUTING 或等价物）——用户预授权必须留在 git 里，不能只活在聊天记录
- [ ] 值守文档 `docs/babysit.md` 的授权分级段改成「见本页」，不再各自展开

**用户授权的形式**：默认合入档生效的前提是用户在会话里明确说过一次「这几类以后不用问我」。**没说过就不生效**，全部按「必须先问」办——本页只是把清单写好等授权，不是授权本身。
