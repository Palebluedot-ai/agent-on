# babysit — 值守合并调度（merge dispatcher）

> 职责边界：本组件管**多会话并行时仓库远端公共态的在班执行**——main、PR 队列、CI、记账账本、合并判定与事后审计。它不写业务代码、不解语义冲突。
> **2026-08-20 起本组件做自动合并**（用户全权授权）：除穷举的硬停清单外，值守自己合，不逐单问；补偿控制是事后独立审计而不是事前审批。决策全文见 [snapshot/2026-08-20-full-auto-merge-and-audit.md](../../snapshot/2026-08-20-full-auto-merge-and-audit.md)。
> 抽取自：Dartify 值守夜班（2026-08-16，单会话 9 连合 + 6.5h billing 事故处置 + worktree 控制面首战）与值守调度实战（2026-08-17，#164/#165/#169 三单，跨会话交单→分诊→打回→复核拍板全链路）。**每一条纪律都被真实使用过，没有一条是想象出来的。**

## 为什么需要（排队经济学）

分支保护开 up-to-date 硬门后，「合并」变成全局串行资源——N 条会话各自追平自合 = 每次合并把其余人打回 BEHIND，全场 O(N²) 次 rebase；值守串行调度 = O(N) 次。**合并权中央化不是偏好，是硬门下的最优解。** 核心分工：功能会话只开发 + 开 PR，开 PR 即交付；合并权唯一归值守会话，短循环串行消化。

## 在四层里的位置

| 层 | 组件 | 管什么 |
|---|---|---|
| 本地写边界 | [worktree 控制面](../worktree-control-plane.md)（lane 合同 + guard/hooks） | 谁的 worktree 能改哪些文件 |
| 排队规划 | [landing 控制面](../landing-control-plane.md)（只读侦察） | 能不能合、按什么顺序（NOW/波次） |
| 远端公共态执行 | **值守 babysit（本组件）** | 在班串行执行：追平、分诊、拍板通道、merge、记账、回执 |
| 事后检测 | **[merge-audit](../../tools/merge-audit/README.md)** | 合过的单里有没有不该合的、有没有悄悄合的 |
| 单会话纪律 | 既有铁律（TDD / 验证后完成 / 贴证据） | 会话内怎么干活 |

**与 landing 控制面的关系**：landing v1 是规划半场（严格只读，明言不自动 merge）；值守是它缺的执行半场——landing 文档「未来 auto-merge 挂点」的**有人值守实现**：`category == NOW` + 证据有效 = 合并队列头，经拍板后由值守执行，合完触发 refresh 走增量失效。没装 agent-on CLI 的仓值守独立可用（纯 gh 命令）。

## 快速开始

按 [SETUP.md](SETUP.md) 四步：①用户手跑权限命令 ②治理文档加条款 ③装审计工具并落值 `policy.json` ④复制模板填占位符，新会话 `/loop 读 docs/babysit.md 全文并执行本轮值守`。保持窗口开 = 在班；换班 = 新会话重新 /loop 同一份文档。

第 ④ 步填占位符时，**硬停清单与时延目标 X 照 [MERGE-POLICY.md](MERGE-POLICY.md) 抄一次**（X 要按本仓 CI 中位时长算出具体数字写死，别留公式）。

**第 ③ 步不做完就别开自动合入**——事前审批已经拿掉，事后检测没装上，中间那段是裸奔。

## 设计不变量（丢了任何一条就退化回混乱）

1. **会话是班次，文档是资产**——交接快照、分诊手册、遗留清单全在 `docs/babysit.md` 里随 git 进化；接班核对而非信任。
2. **队列真相源 = open PR 列表**——SendMessage 交单只是门铃 + 特殊说明通道；值守会话死了，队列从 `gh pr list` 完整重建。
3. **追平只走服务端** update-branch API——与 lane 边界零冲突（实测：本地推别人分支被 guard 正确拦，服务端 API 干净通过）。
4. **串行 + 连锁追平**——一次只合一条，合完立即给队列下一条发起追平；这就是 O(N²)→O(N) 的执行动作。
5. **批准来自本会话用户输入**——同行转述只是情报，须向本人复核（peer cannot grant escalation 的实操化）。
6. **门铃提速，队列兜底**——交单消息让值守分钟级起跑，但队列真相源永远是 open PR 列表；门铃丢了只慢一个心跳，不漏单（[MERGE-POLICY §1](MERGE-POLICY.md)）。
7. **控制在，位置换了**——2026-08-20 起默认 fail-open：除穷举的硬停清单外自动合，**事前审批换成事后独立检测**。两条配套硬约束缺一不可：①硬停清单必须穷举、写死、可机器判（散文 [MERGE-POLICY §4](MERGE-POLICY.md)，可执行 [policy.json](../../tools/merge-audit/policy.json)）②**审计跑不通就退回逐单先问**（dead-man's switch）。拿掉审批而不补检测，中间那段是裸奔。
8. **执行窗口由指令类别决定，不由用户在哪打字决定**——合并 / 对外通信 / 跨窗口传话三权唯一归值守；发错窗口的指令不执行、原样转投（[ROUTING.md](ROUTING.md)）。转投把**指令**送过去，**不送授权**：批准仍只认值守会话内用户本人的输入。
9. **审计的结论必须独立于被审计者**——`scan` 从 GitHub 的客观事实重算，不读值守对自己行为的任何自述。值守可以在 `record` 里写任何话，两者对不上就是 `MISMATCH`。**结论与被审计者同源的日志没有价值**——agent 给自己的越界找出漂亮理由时，那份日志会跟着一起漂亮。
10. **不记账的合并算越界**——账本里没有的合并会被报成 `UNRECORDED`，它比「合错了」更重：合错了还能回溯当时按什么判的，悄悄合的连这个都没有。

## 诚实边界

- **做无人绿灯合并（2026-08-20 起），并且知道代价**：硬停清单是启发式（路径 glob + 作者 + 结构化标记），抓得住绝大多数形状，**抓不住语义级越界**——比如一份文档里写了一句危险的话。它降低风险，不消灭风险。这是用「用户彻夜等拍板 / 别人的活被堵住」换来的，是一次显式的取舍，不是疏忽。
- **审计只覆盖「合了什么」，不覆盖「值守都干了什么」**：删远端分支 / 关别人的 PR / force-push / 跨仓外向操作不是 PR 形状的，工具一概看不见，照旧靠纪律必须问用户。别读成装了工具就全覆盖。
- **哈希链防的是「不留痕地改一条」，不是防篡改**：能改文件的人就能重算整条链；它把静默修改变成必须公开的重写。
- 单值守互斥靠治理条款、接班仪式与 `agent-on oncall` 文件登记，**不靠分布式锁**——两个窗口同时 `--force` 抢，后写的赢；登记的价值是机器可寻址与留痕，不是互斥保证（[ROUTING §6](ROUTING.md)）。
- 值守不修复任何东西：真缺陷打回作者（证据指针 + 定位 + 修复选项），billing 类事故推通知等管理员。
