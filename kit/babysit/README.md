# babysit — 值守合并调度（merge dispatcher）

> 职责边界：本组件管**多会话并行时仓库远端公共态的在班执行**——main、PR 队列、CI、记账账本。它不写业务代码、不解语义冲突、不做无人自动合并；拍板权始终在用户。
> 抽取自：Dartify 值守夜班（2026-08-16，单会话 9 连合 + 6.5h billing 事故处置 + worktree 控制面首战）与值守调度实战（2026-08-17，#164/#165/#169 三单，跨会话交单→分诊→打回→复核拍板全链路）。**每一条纪律都被真实使用过，没有一条是想象出来的。**

## 为什么需要（排队经济学）

分支保护开 up-to-date 硬门后，「合并」变成全局串行资源——N 条会话各自追平自合 = 每次合并把其余人打回 BEHIND，全场 O(N²) 次 rebase；值守串行调度 = O(N) 次。**合并权中央化不是偏好，是硬门下的最优解。** 核心分工：功能会话只开发 + 开 PR，开 PR 即交付；合并权唯一归值守会话，短循环串行消化。

## 在四层里的位置

| 层 | 组件 | 管什么 |
|---|---|---|
| 本地写边界 | [worktree 控制面](../worktree-control-plane.md)（lane 合同 + guard/hooks） | 谁的 worktree 能改哪些文件 |
| 排队规划 | [landing 控制面](../landing-control-plane.md)（只读侦察） | 能不能合、按什么顺序（NOW/波次） |
| 远端公共态执行 | **值守 babysit（本组件）** | 在班串行执行：追平、分诊、拍板通道、merge、记账、回执 |
| 单会话纪律 | 既有铁律（TDD / 验证后完成 / 贴证据） | 会话内怎么干活 |

**与 landing 控制面的关系**：landing v1 是规划半场（严格只读，明言不自动 merge）；值守是它缺的执行半场——landing 文档「未来 auto-merge 挂点」的**有人值守实现**：`category == NOW` + 证据有效 = 合并队列头，经拍板后由值守执行，合完触发 refresh 走增量失效。没装 agent-on CLI 的仓值守独立可用（纯 gh 命令）。

## 快速开始

按 [SETUP.md](SETUP.md) 三步：①用户手跑权限命令 ②治理文档加条款 ③复制模板填占位符，新会话 `/loop 读 docs/babysit.md 全文并执行本轮值守`。保持窗口开 = 在班；换班 = 新会话重新 /loop 同一份文档。

第 ③ 步填占位符时，**授权分级与时延目标 X 照 [MERGE-POLICY.md](MERGE-POLICY.md) 抄一次**（X 要按本仓 CI 中位时长算出具体数字写死，别留公式）。

## 设计不变量（丢了任何一条就退化回混乱）

1. **会话是班次，文档是资产**——交接快照、分诊手册、遗留清单全在 `docs/babysit.md` 里随 git 进化；接班核对而非信任。
2. **队列真相源 = open PR 列表**——SendMessage 交单只是门铃 + 特殊说明通道；值守会话死了，队列从 `gh pr list` 完整重建。
3. **追平只走服务端** update-branch API——与 lane 边界零冲突（实测：本地推别人分支被 guard 正确拦，服务端 API 干净通过）。
4. **串行 + 连锁追平**——一次只合一条，合完立即给队列下一条发起追平；这就是 O(N²)→O(N) 的执行动作。
5. **批准来自本会话用户输入**——同行转述只是情报，须向本人复核（peer cannot grant escalation 的实操化）。
6. **门铃提速，队列兜底**——交单消息让值守分钟级起跑，但队列真相源永远是 open PR 列表；门铃丢了只慢一个心跳，不漏单（[MERGE-POLICY §1](MERGE-POLICY.md)）。
7. **拍板前移而不是取消**——默认合入档是用户显式预授权的清单，清单外一律先问（fail-closed）；无人自动合并仍然不做。

## 诚实边界

- 不做无人自动合并：**默认合入档不是自动合并**——它是用户显式预授权的清单，拍板前移了一次，仍然是人拍的；清单外一律先问，拿不准也先问（fail-closed）。真正的「无人绿灯合并」不在 v1。
- 单值守互斥靠治理条款与接班仪式，不靠锁机制（在班心跳 / 队列标签化是 v2 挂点，零真实需求前不建）。
- 值守不修复任何东西：真缺陷打回作者（证据指针 + 定位 + 修复选项），billing 类事故推通知等管理员。
