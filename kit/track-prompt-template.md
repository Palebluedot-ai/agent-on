# 执行任务派工 Prompt 模板

> 职责边界：把一个已明确的目标交给执行会话。路径、依赖、结果回执按需填写；不按模型品牌强制加脚手架，不按页面自动开 worktree。

先把共享组件、全局样式、路由、锁文件归到一个任务。依赖未集成的消费者排队。独立执行确有必要时，再选窗口和隔离树，执行书见 [巡逻协调与派工](patrol-control-plane.md)。

```text
你负责 [项目 / 任务 id]。
目标：[用户要得到的结果]
工作目录：[实际绝对路径；现有树或明确创建的隔离树]
共享修改归属：[本任务负责的路径；其他任务负责的共享面]
依赖：[已集成的结果 / 尚需等待的任务 / 无]
验收：[可观察行为与必要检查]

在已确认的范围内直接推进。claim/owns 可作记账，不是开工前提。
发现实际共享修改重叠时，通知入口协调；值守在班则由值守中转和合入。
低风险实施选择自行决定并说明；改变产品方向、权限或不可逆操作按已有授权处理。

按影响验证：行为、数据与权限变动优先复现失败并回归；样式与文案看预览和交互。
保留真实失败和未验证事项，满足项目 required CI，不用旧绿灯证明新代码。
不替其他窗口 stash、提交、清理。对本任务提交和交付按项目规则执行。

结果：完成了什么；实际检查输出或证据位置；仍缺什么；共享修改与下一步。
有多个任务或真实拍板项时参考 kit/output-contract.md，其余用短报告。
通过宿主结束 hook 或 agent-on task result 回传结果；报告不自动算已验证或已释放。
确认会话退出、任务结果已收口后，带证据 agent-on task release <id>。
```

新增强制句必须来自真实返工证据。能力探针只在任务不确定性值得测试时使用；不因换模型品牌把整套流程重新跑一遍。
