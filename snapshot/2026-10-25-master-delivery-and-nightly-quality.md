## 实施范围

1. 默认沿 deliver → status → master 交付。Matt 的小接口/深模块、完整工作包、需求与约定两轴审查内化；不要求安装完整插件、不叠加多套 review。
2. 实际 Git 提交/推送从诊断报告分离。坏 lane JSON、失效历史 base、别的 checkout 暂停重放不会锁住本次写入；临时裸仓测试 push 不作为线上 main 写入。实际活跃同文件冲突判据保留。
3. master 复用 oncall/landing/独立 merge-audit。READY / WAIT / FIX / HARD_STOP 分开，按当前 head 合入，审计账共用；先落未完成回执，中断核实际 GitHub 状态后补账。没有 lane 也可交付，坏缓存重建，旧记录留诊断。未新增模型、消息、后台调度运行时。
4. 依赖合入证明独立于 janitor/GC 扫描，保留 released head、目标分支与 squash head 覆盖判据。
5. PR 按范围运行机械检查；共享基础、未知 Rust 范围与检查器变化执行全量；夜间香港时间 01:23 全量，在 GitHub 托管 runner 上运行。保留原 job 名称，步骤内跳过无关执行。合入后不再重复 push CI。
6. Dashboard、巡逻、清理与型号诊断保留兼容、退出日常主线。握手不因陈旧网页/计数/旧树主动加手续。返工与误拦引用已有项目记录，settle/digest 按需补收。
