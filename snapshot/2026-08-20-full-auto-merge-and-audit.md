# 全自动合并 + 独立审计：把事前审批换成事后检测（2026-08-20 决策快照）

> 职责边界：本页记**这次拍了什么、为什么这么拍、拿什么证据、哪些地方还是漏的**。
> 机制正文在 [kit/babysit/MERGE-POLICY.md](../kit/babysit/MERGE-POLICY.md) §3/§4（授权口径的唯一真相）
> 与 [tools/merge-audit/](../tools/merge-audit/README.md)（审计工具），本页不重复展开判据表。
> 触发：2026-08-20 用户原话——「现在开始，You have all my full authorization，除特殊情况外我们全自动合并，
> 不要再等我手动合了。手动合并非常耽误时间，晚上开发时如果没合，其他人的程序就没法进行。」
> 同一条指令的第二半：「我们要额外做一个记录 log 的 side project 小工具……判定哪些是不应该合并的，并记录下来……
> 先记录并监控它有没有一些越界的行为，或者合了不该合的内容，避免出现安全隐患。」
> 并明确：「如果以上调整与之前写的文档规定有任何冲突，一律以本次的要求为主。」

## 一句话

**控制从「事前问」换成「事后查」。** 默认从 fail-closed 翻成 fail-open：三查过即自动合，
只留一张穷举的硬停清单；同时补上一个**独立于值守判断**的审计工具，
把每一次合并事后重判一遍，专门找「合了不该合的」和「悄悄合的」。

**这两半是一件事，不是两件。** 拿掉事前审批而不补事后检测，中间那段是裸奔。

## 拍了什么（四条）

1. **默认翻面**。原口径是「清单内的几类可自动合，**清单外一切**必须先问」（fail-closed）；
   新口径是「**除硬停清单外一律自动合**」（fail-open）。硬停清单必须穷举、写死、可机器判。
2. **硬停四类**（永不自动，必须问用户）：①闸与权限自身（`.claude/settings*.json` · `hooks/` ·
   `.github/workflows/` · `cli/src/{guard,oncall,routing}.rs` · **以及审计工具自己 `tools/merge-audit/`**）
   ②凭据与密钥 ③不可逆的文件改动（迁移脚本 / SQL）④外部作者的 PR（供应链）。
3. **「带 breaking / 迁移标注」从硬停降为「需播报」**：照常自动合，但值守当轮必须向用户播报一行。
   理由见下面的设计选择表第 3 行。**这条是本轮唯一一处放宽了旧清单的地方，单独标出来等用户复核。**
4. **自动合并的生效条件 = 审计工具跑得通**。`merge-audit report` 跑不起来（工具没装 / `gh` 没登录 /
   账本链断了）时，值守**退回 fail-closed**，按旧规矩逐单问。这是一个 dead-man's switch：
   检测面塌了，放开的那一半自动收回去。

## 为什么（问题的形状）

**旧机制的两半，只剩一半在跑，而剩下那半正在制造损失。**

- 值守窗口的价值本来是两半：**串行合并权**（N 条会话各自追平自合是 O(N²) rebase）与
  **少让用户拍板**。08-20 早些时候刚由 [#35](https://github.com/Palebluedot-ai/agent-on/pull/35) /
  [#36](https://github.com/Palebluedot-ai/agent-on/pull/36) 补过一次第二半（「内容拍过板的单不问第二遍」），
  但那次只解决了「同一件事问两遍」，**没解决「没人拍过板的单要等用户醒着」**。
- 用户这次说的是后者，而且给了具体的损失形状：**「晚上开发时如果没合，其他人的程序就没法进行」**。
  在多会话并行的仓里，未合的 PR 不是「等一等」，是**别人的活被堵住**——
  一条 PR 卡在等拍板，下游每条会话都在 BEHIND 上原地打转。
- 于是「先问」这个控制的代价不再是噪音，是**吞吐**。而它买到的安全，
  在本仓的实际形态是「用户看一眼 PR 标题然后说合」——这层审批的信息含量本来就接近零。

**但直接拿掉审批，等于把「agent 会不会合不该合的」这个风险敞口全开。** 用户自己点破了这一点，
所以第二半要求的不是日志，是**判定 + 记录 + 监控越界**。

## 三个设计选择（各附被否掉的替代）

| 选择 | 选了什么 | 否掉了什么 | 为什么 |
|---|---|---|---|
| 补偿控制放哪 | **事后独立复判**：审计工具从 GitHub 客观事实重算，不读值守的自述 | A：值守自己写 log（它说自己干了什么）· B：只留一个「合完通知用户」 | A 的结论和被审计者同源——agent 给自己的越界找出漂亮理由时，那份 log 会跟着一起漂亮。**独立性是这个工具唯一的价值来源**：值守可以在 `record` 里写任何话，`scan` 照样从真实文件清单 / 作者 / 检查结论重算。B 不产生可查的账，事后无法回溯 |
| 硬停清单按什么判 | **PR 的客观事实**：文件路径 glob · 作者是否受信 · 结构化标记行 · 检查/评审结论 | 自由文本搜索 PR 正文里的危险词 | 首次对着本仓真实历史跑就抓到了：`#35`/`#36` 正文里讨论「删远端分支」「BREAKING」，被判成硬停。**方法论仓的正文天天在讨论这些词**，自由搜索必然误报，而误报会训练人忽略告警。改成整行前缀（`BREAKING:` / `迁移注记：`）+ 标签后归零 |
| breaking 标注还硬停吗 | **降为「需播报」**：自动合 + 当轮必须出声 | 保留在硬停清单（值守会话的建议） | 那五类不可覆盖清单的**成立理由是「撤不回来 / 动的是别人的东西」**；breaking 标注在本仓（文档 + Rust CLI）是可 `git revert` 的，它落在这条理由之外。它真正的价值是**信号**——那就用播报兑现信号，不用阻塞兑现。**同时保留一句诚实话：这是本轮唯一一处比旧清单松的地方，`policy.json` 里挪一行就能改回去** |

## 值守会话提的两条，怎么处理的

08-20 值守窗口（`worktree-output-clarity-e02325`）在收到预告时提了两条，都采纳了：

1. **「硬停清单必须穷举且写死，请照旧的五类逐条对齐」** → 逐条对齐了，四类覆盖旧的第 1/2/3/4 类；
   旧第 5 类（breaking）明确降级并单独标出待复核，**不是漏掉，是改了并说出来**。
2. **「审计工具是这条方案能成立的关键，别当附属品；工具落地之前自动合并是否生效？我判断不该」** →
   采纳，落成上面拍板第 4 条（dead-man's switch），并且两半在**同一个 PR 里**落地，不分批。

值守同时拒绝按转述执行这条授权（「常驻预授权 vs 单次转述」，见
[snapshot/2026-08-20-standing-preauthorization.md](2026-08-20-standing-preauthorization.md)），
这是对的——**本页 + 本轮 PR 就是把口头授权换成 git 里可核验条款的那一步**。

## 诚实边界

- **工具看的是「合了什么」，不是「值守都干了什么」。** 删远端分支 / 关别人的 PR / force-push /
  跨仓外向操作不是 PR 形状的，本工具一概看不见。那一半仍然靠纪律，不靠机器——
  写在这里是为了别让人误以为装了工具就全覆盖了。
- **规则是启发式，不是证明。** 路径 glob 与结构化标记抓得住绝大多数形状，抓不住
  「一份文档里写了一句危险的话」这种语义级越界。它降低风险，不消灭风险。
- **哈希链防的是「不留痕地改一条」，不是防篡改。** 能改文件的人就能重算整条链；
  它的作用是把静默修改变成必须公开的重写。
- **`ledger_starts_at` 之前的合并不产生记账类发现。** 那时还没有账可对；
  但越界类发现（合了不该合的）不受此限。
- **本轮只落了模板层 + 工具。** 本仓真正生效那一步是 `docs/babysit.md` §3 落值 +
  `CHANGELOG.md` 条目，两处在值守轨 owns 里，本轨写不了，随 PR 走接线单交值守。
  **在 `docs/babysit.md` §3 落值之前，本仓仍按旧口径跑。**
- **「谁来合」一字未动**：三权唯一（合并 / 对外通信 / 跨窗口中转归在班值守）与串行合并权照旧。
  本条只改「合之前要不要问用户」。
