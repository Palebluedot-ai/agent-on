# 常驻预授权：内容拍过板的单，合并是机械步骤（2026-08-20 决策快照）

> 职责边界：本页记**这次拍了什么、为什么这么拍、拿什么证据**。机制正文在 [kit/babysit/MERGE-POLICY.md](../kit/babysit/MERGE-POLICY.md) 的 §3 第 5 类「内容已拍板的单」与 §4「批准的两种载体」（唯一真相），本页不重复展开判据表。
> 触发：2026-08-20 用户原话——「在值守窗口可以不问我合不合么，直接合，怎们突然还需要再问我了呢？那岂不是没有作用了么」。
> 拍板：同日用户「选A」（三选一里的 A：内容已拍过板 → 合并算机械步骤）。

## 一句话

**合并这个动作本身不产生新决定时，它是机械步骤。** 内容拍板发生在作者会话；到值守窗口再问一遍「合不合」，第二遍不产生任何新信息，只产生噪音。判据从「这单碰了什么」补上一条「这单的内容有没有人拍过板，指针在不在 git 里」。

## 拍了什么（三条）

1. **默认合入档新增第 5 类「内容已拍板的单」**：用户本人在作者会话拍过内容，且拍板**在 git 里核得到**（PR 描述「拍板」段 · `decision(...)` commit · CHANGELOG 未发布条目 · `snapshot/` 快照，四选一），且**实际 diff 不超出拍板范围**。核不到 / 超范围 → 整单降级回「必须先问」。
2. **必须先问档划出「永不被覆盖」的五类**：权限配置 · 数据库迁移与一切不可逆动作 · 删远端分支/关别人的 PR · 跨仓跨账号外向操作 · 带 breaking 或迁移标注的 PR。理由不是「用户要知道」而是「撤不回来 / 动的是别人的东西」，拍过板也不改变。其余三类（功能代码 · 治理文档 · CI 与依赖）在指针核得到时归第 5 类。
3. **区分常驻预授权与单次转述**：写进 git 的条款 = 常驻，直接认；聊天记录里转述的一句「合了吧」= 一次性情报，仍须本人复核。**#169 那条地基一字未松**——它管的是转述那一栏。

## 为什么（问题的形状）

**双重拍板**：同一个决定被问两遍，第二遍绕一个窗口且零信息量。

- 用户在作者会话看着 diff 拍了「这么改」；PR 开出来交给值守，值守按旧规矩把它归进「必须先问」，于是用户在值守窗口再拍一次「合不合」。
- 在 agent-on 这种「几乎每单都动核心内容」的仓里，[docs/babysit.md](../docs/babysit.md) 的「必须先问」第一行就把 `kit/` `playbook/` `bench/` `boot/` `cli/` `skill/` `hooks/` `AGENTS.md` 的语义改动全括进去了（当初写这行的理由成立：这里的内容就是方法论本身）。结果是**值守窗口「少让用户拍板」那半个目标在本仓约等于零**，用户拍两遍还多绕一个窗口——用户原话「那岂不是没有作用了么」，指的正是这半。
- 而它跟前一天刚立的规矩打架：[playbook/multi-contributor-protocol.md](../playbook/multi-contributor-protocol.md)「外向硬门的边界」一节配套第 1 条**授权幂等**写着「逐次问不是更安全——它把幂等的授权当成非幂等，噪音会淹掉真正该问的那一次」。**同一套方法论两处口径拉反方向**——正是 [bench 案例 39](../bench/cases/39-harness-boilerplate-as-project-rule.md) 自己写下的病名，当时没把 merge 本身算进去。

## 三个设计选择（各附被否掉的替代）

| 选择 | 选了什么 | 否掉了什么 | 为什么 |
|---|---|---|---|
| 放开多宽 | **只放开「同一件事问第二遍」**（A） | B：三查全过一律直合，只留四类先问 / C：只补几个窄类（CHANGELOG 回填、snapshot、bench 入册） | B 把「真正该问的那一次」也一起关了，等于用噪音问题换失控问题；C 完全没碰到痛点——用户的痛点就是 canonical 语义单，而 C 恰好把它留在原地 |
| 授权凭什么可信 | **git 里核得到的指针**（四选一，写死形式） | 交单消息里作者会话的一句「用户拍过了」 | 后者就是 #169 判死的转述路径：核不到、审不了、撤不掉。**指令能转投，授权不能**——把授权挂在可核验的 git 对象上，才既松了噪音又没动地基 |
| 授权住在哪 | **git 里的条款**（本页 + MERGE-POLICY §3 + 项目 `docs/babysit.md` §3） | 聊天记录里用户说过的一句话 | 值守是**班次**不是长驻会话，换一班换一条会话，聊天记录不跟着走。授权只活在某一班的上下文里 = 每次换班都要用户重说一遍，机制自己把自己耗光 |

## 证据

- 用户原话（本轮触发）：「在值守窗口可以不问我合不合么，直接合，怎们突然还需要再问我了呢？那岂不是没有作用了么」
- 旧口径三处：`kit/babysit/MERGE-POLICY.md` §3 原五类（无「内容已拍板」）· 同页 §4「批准只认本会话内的用户输入」· `docs/babysit.md` 必须先问档第一行「合并一切 canonical PR……**本仓绝大多数 PR 在此**」
- 反方向口径：`playbook/multi-contributor-protocol.md` 三½.7 配套 1「授权幂等：同一项目内同类动作一次点头长期有效，不逐次追问」（2026-08-19 立，PR #27）
- 授权从未生效的机器证据：`docs/babysit.md` §3 第 5 类要求「值守要在 §5 记一行——哪一类、哪天拍的」，而 §5 遗留清单里**零条**这样的记录 → 本仓默认合入档实际上从来没被激活过
- 「预授权必须留在 git」不是本轮发明：`kit/babysit/MERGE-POLICY.md` §8 接入清单原本就写着「用户预授权必须留在 git 里，不能只活在聊天记录」——本轮是把这条要求兑现，不是新增

## 诚实边界

- **核的是「存在一条拍板记录」，不是「那条记录确实覆盖这个 diff」**。后半仍靠值守读 diff 判断，没有机械闸。写死的补偿是两条：diff 超范围整单降级、合完必须把指针记进账本（记不下指针 = 等于没核过）。
- **本轮只落了机制唯一真相那一半**。`playbook/multi-contributor-protocol.md`（三½.6 配套 1 的口径对齐）、`docs/babysit.md` §3（本仓具体值 = 授权正式生效的那一步）、`CHANGELOG.md`、`bench/cases/README.md` 索引行四处被 live 轨占住（`dtcg-post-landing-revalidation` [ready] 与在班值守轨 `worktree-output-clarity-placeholder` [active]），本轨写不了，走接线单交值守派工。**在 `docs/babysit.md` §3 落值之前，本仓的第 5 类还没生效**——MERGE-POLICY 是模板层，项目层没落值就还是「清单挂好等授权」。
- **本条不改「谁来合」**。三权唯一（合并 / 对外通信 / 跨窗口中转归在班值守）与串行合并权一字未动；本条只改「合之前要不要再问一遍用户」。
- **不引入无人自动合并**。第 5 类的每一单背后都有一次用户拍板，只是拍在更早、拍在别的窗口。
