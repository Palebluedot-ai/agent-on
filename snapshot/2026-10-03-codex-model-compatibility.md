# 2026-10-03 · 型号拒绝排错与用户选型权

> 职责边界：本页记录本轮决策演进、当前边界与续接事项，不另造任务台账或执行规则。当前方法论在 `playbook/model-playbook.md`，启动约定在 `kit/patrol-control-plane.md`；完整排错与验证证据在 [唯一排错记录](../memory/2026-10-03-codex-model-compatibility.md)。

## 会话摘要

用户先要求系统性解决默认型号被账户拒绝，随后明确不固定型号，最后拍板：规划、执行用谁、哪款模型由用户决定，Agent-On 只按明确指令调度和编排。本轮据此撤回未发布的自动型号/档位兜底，落实到启动、重试、精确续接及旧回执读取，不启动新模型窗口。

## 关键决定

- 用户拥有阶段、执行工具、模型与推理档位的选择权；Agent-On 不因能力印象、价格、空闲、目录推荐或失败自动选型、改派或降档。
- 未指定型号不构成缺失前提：沿用宿主当次设置；显式型号按原值传递，不额外问一次确认、不替换、不写全局配置。
- `model-check` 是主动、只读的可选诊断，不进入启动路径，不根据目录选择替代者。真正启动/宿主失败保留任务与现场、如实报告；后续换号需用户新指令，不重放工具。
- 当前权责符合既有工具/模型无关原则，不改 CHARTER、宿主认证/权限、值守三权或合流/回收政策，不授权安装或发版。

## 发现

此前两版未发布实现分别采用原生目录唯一默认兜底、随后放宽元数据检查门槛，但都还允许不兼容默认自动换号，现已被最新决定取代。先红测试证明旧回执的 selected_model 与 reasoning_effort_override 会进入真实子进程参数；新实现只信 session.model，刷新回执为 explicit 或 host-settings / not-probed。这个记录是指令依据，不冒充实际使用型号或账户资格。

早期本机真实登录 Codex 的只读工具调用与自动状态接续成功，只验证当时的单次兼容路径，不是现在自动换号的授权；不把旧成功拿来声明新政策下真实账户调用已通过。

## 本轮改动

- `cli/src/codex_model.rs` / `coordination.rs` / `main.rs`：启动不读目录、不自动选型或档位；旧兜底回执不能成为覆盖，诊断配置不兼容明报。
- `cli/tests/model_compatibility.rs`：旧回执、显式选择、无目录查询、默认启动、重试/精确续接和实际 host 失败的子进程回归。
- `playbook/model-playbook.md` / `kit/patrol-control-plane.md`：方法论与执行书成对落实用户选择权；旧混编建议、索引、看板说明、CHANGELOG 与 AGENTS 状态同步对齐。
- 本页与排错记录保留被取代的历史事实，不维护第二套型号决策或任务状态数据库。

## 续接顺序

1. 保留同一入口与既有共享源码改动，按排错记录核验证输出；不重新初始化、不自动创建 worktree。
2. 用户明确阶段顺序和执行工具/模型后，才在已接适配器范围执行交接；未接工具诚实报告，不擅自改派。
3. 安装/发布、真实其他宿主接线与自动阶段流水线另核范围、授权和证据；如后续 commit 交付，遵本仓 annotated tag 与原子推送纪律。
