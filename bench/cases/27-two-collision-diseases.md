# 案例 27:互踩 ≠ 撞题 ≠ 撞号——三种并行事故三种解药

> 层级:L2 教训 | 来源:Euan-Flutter 2026-07-30 harness 审计 + 晚间 D24 撞号 | 入册:第十五/十六次消化

## 症状
同仓并行三类「撞车」易被混治:
1. **互踩**:test/analyze 把错报在没碰过的文件上——多分支挤一工作目录。
2. **撞题**:同 base 各自独立做同一主题/同文件。
3. **撞号**:两条会话同取决策号 D24,rebase 才暴露 requirements 单行冲突。

## 根因
三病三因:环境未隔离 / 意图未广播 / **共享顺序编号未原子占号**。worktree 与开工声明治不了第三型。

## 修法
- 互踩 → 每会话独立 worktree。
- 撞题 → 开工前状态面声明主题(广播非锁)。
- 撞号 → 取号即落盘占位;撞了先合先得 + 后者改号扫全仓引用。

## 可复用规则
并行事故先分型再立规;禁会话数是误诊。
