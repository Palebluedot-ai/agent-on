# 案例 27:互踩 ≠ 撞题 ≠ 撞号 ≠ 主题撞题——四种并行事故

> 层级:L2 教训 | 来源:Euan-Flutter 2026-07-30 + Dartify 2026-08-02 | 入册:第十五/十六/十九次消化

## 症状
同仓并行四类「撞车」易被混治:
1. **互踩**:test/analyze 把错报在没碰过的文件上——多分支挤一工作目录。
2. **工作重复**:同 base 各自独立做同一主题/同文件(意图未广播)。
3. **撞号**:两条会话同取决策号 D24。
4. **主题撞题(分钟级)**:开工查过 PR 列表,提交前别人又开同题 PR——只查一次全盲(Dartify #55/#59 各修一遍限流 IP,实现逐字相同)。

## 根因
四病四因:环境未隔离 / 意图未广播 / 编号未原子占号 / **查重只在开工一刻**。

## 修法
- 互踩 → 每会话独立 worktree。
- 工作重复 → 开工声明主题(广播非锁)。
- 撞号 → 取号即落盘;先合先得 + 后者改号。
- 主题撞题 → **开工前 + 提交前**各 `gh pr list` 按主题;撞了 handoff 不抢轨。

## 可复用规则
并行事故先分型再立规;禁会话数是误诊。
