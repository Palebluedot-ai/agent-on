# 案例 27:互踩 ≠ 撞题——两种并行事故两种解药

> 层级:L2 教训 | 来源:Euan-Flutter 2026-07-30 harness 审计(PR #23 + 87205ce/PR #21) | 入册:2026-07-30 第十五次消化

## 症状
同仓同日两类「撞车」被混谈、混治:
1. **互踩**:PR #23 记录 test/analyze 把错误报在自己没碰过的文件上——5 条分支挤一个工作目录。
2. **撞题**:87205ce 与 PR #21 同 base、同 3 文件、各自独立做「第九轮底栏」——`git merge-base` 双证冲突。

若一律「禁并行/禁同目录」,会把并行收益一起砍掉。

## 根因
两病不同因:互踩是**环境未隔离**;撞题是**意图未广播**。同一味药治不了两种病。

## 修法
- 互踩 → 强制每会话独立 git worktree(隔离归机制)。
- 撞题 → 开工前在唯一状态面(progress/dashboard/handoff)声明主题——声明是广播,不是独占锁。
- 禁会话数 / 无差别禁同目录 = 误诊。

## 可复用规则
并行事故先分型:环境互踩用 worktree;工作重复用开工声明。
