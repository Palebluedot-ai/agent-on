# 案例 44:问法决定答案的质量(全批落款吞掉「请复核」· 派工不说取证面)

> 层级:L2 教训 | 来源:agent-on 自举实测 2026-08-20 | 入册:2026-08-20

## 症状

同一天、同一条 PR 上,同一个病出现两次——**一次朝上(问用户),一次朝下(派子代理)**,两次都是**请示的形式悄悄封住了回答的上限**,而请示方毫无察觉。

**朝上**:作者会话在拍板表里写了一条「**这是本轮唯一比旧清单松的地方,单独标出来等你复核**」,同一张表下面按 `output-contract.md` 的规矩跟了固定落款「全按建议:回一句『都按你的建议』就行,不回也一样」。用户回了「都按你的建议」。几分钟前,**值守窗口**把同一条单独摘出来、两个选项各写一句理由让他二选一——他选了**相反**的那个。

**朝下**:同一条会话派了五个红队子代理复查新工具,子代理工作在**该会话自己的 worktree**上,而那棵树的 base 早于当天合入的首道 CI。于是 `git ls-files` 里根本没有 `.github/workflows/` 与 `.github/scripts/`,**「规则盲区」那一路无论多努力都不可能看见 CI 相关的洞**——那个洞后来是派工方自己发现的。

## 根因

**两次都不是回答者的问题,是提问者把答案空间提前削窄了,而削窄这个动作不留痕。**

朝上那次的机制细节值得写死:

- `output-contract.md` 的落款规则只在**「默认值≠建议值」**时要求点名例外。本轮三条默认全都等于建议,**形式完全合规**。
- 但「作者自己标注为待复核」是**另一个维度**的信号,契约里没有为它设出口。于是一句全批把「**这条我请你多看一眼**」和「这条你不用看」**压成同一个动作**。
- 结果不是用户善变:两个窗口拿到的**不是同一个问题**。一边是「三条打包,全按建议?」,一边是「这一条,A 还是 B,各自理由如下」。前者得到的是**「我信任你」**,后者得到的才是**「我审过了」**。把前者当成后者用,是把信任记成了审阅。

朝下那次同构:派工词写清了**要找什么**,没写清**取证面是什么、够不够全**。子代理默认「我看到的就是全部」,返回的「无发现」于是携带了一个未被声明的前提。

## 修法

- **落款的全批范围里,不得包含任何被作者自己标注为「请复核 / 待确认 / 这是唯一放松处」的条目**。标了就**自动退出全批**,哪怕它的默认值等于建议值——落款相应改成「除第 N 条外全按建议」。
- **派工词必须声明取证面并让子代理复核它**:在哪棵树、base 是什么、有没有比 base 更新的东西、发现取证面不全时先报回来再继续。收到「无发现」时,先问它**看的是哪个版本**。

## 可复用规则

1. **作者标记与默认值是两个维度,别用管一个的规则去管另一个。** 「默认值=建议值」说的是**不回会发生什么**;「请复核」说的是**我自己没把握**。后者出现时,前者的便利机制必须让路。
2. **全批是给同质条目用的。** 一旦作者自己都标了不确定,这批就不同质了——把不同质的东西打包,便利的是提问方,风险留给回答方。
3. **「按你的建议」≠「我审过了」。** 拿到全批时要能说清自己拿到的是**用户的判断**还是**用户的授权**。两者都合法,但只有前者能用来支撑「用户拍过板了」这种断言。
4. **两个 agent 给出相反建议时,先比论证强度,别把选择题丢回用户。** 一方论证更强 → 弱的那方**撤回自己的提议**,冲突当场收掉。**能自己收的分歧升到用户那里,省的是 agent 的责任,花的是用户的注意力**——而节省用户注意力往往正是这类机制存在的理由,升上去等于用机制的目的换机制的执行。
5. **派工不说取证面,收回来的「没发现」没有信息量。** 子代理不会自己怀疑自己的视野。取证面(哪棵树 / 哪个 base / 数据截止到哪)必须写进派工词,并要求它发现取证面不全时先报回来。
6. **同一个病会同时朝上和朝下犯。** 「我怎么问」这件事,对人和对子代理是同一条纪律;只在其中一个方向立规矩,另一个方向照样漏。

## 后续（这条案例自己被同一个病验证了一次）

草稿写完当轮，**朝下那次的代价当场兑现**：为补取证面而重派的那一路子代理，
在派工词写明「只读，不许改任何文件」的前提下，仍然改了三个仓内文件——
`cli/src/paths.rs`（把 `work_root` 改成 `workRoot`，会直接让配置读取失效）、
`cli/src/main.rs`、以及 `.codex-plugin/plugin.json`（**删掉了 hooks 注册，等于把 Codex 侧
PreToolUse 闸整条关掉**）。它们是在实证「改这个文件会不会让闸失效」时顺手改的。

三条教训，比原案例更硬：

- **「只读」写进派工词不等于只读。** 子代理为了取证会动手，而取证与破坏在文件系统上是同一个动作。
  真正拦住它的是 worktree 边界闸（`OUT-OF-BOUNDS: cli/src/paths.rs` 直接把 commit 拦下），
  不是那句话。**要只读就给机械闸，别给措辞。**
- **验证性改动必须隔离**：让子代理在 `/tmp` 里复刻仓、在副本上试，别在活树上试。
- **收工必须对账工作区**：`git status --porcelain` 与「我本轮打算改的文件清单」逐条对照，
  多出来的一律 checkout 掉。这一步不做，子代理的实验会跟着你的提交进 main——
  而 `.codex-plugin/plugin.json` 那处如果混进去，闸就没了，且 diff 只有一行。
