# 案例 41:值守窗口的双重拍板(同一个决定问两遍,第二遍零信息量)

> 层级:L2 教训 | 来源:agent-on 自举实测 2026-08-20 | 入册:2026-08-20

## 症状
用户在作者会话看着 diff 拍了「这么改」,PR 开出来交给值守,值守把它归进「必须先问」,于是用户在**值守窗口再拍一次**「合不合」。用户反问:「在值守窗口可以不问我合不合么,直接合,怎们突然还需要再问我了呢?那岂不是没有作用了么。」

## 根因
判据只看**这单碰了什么**(路径 / 文件类型),不看**这单的内容有没有人拍过板**。于是内容型 PR 一律落进 fail-closed 那一栏——而「内容型」在方法论仓、文档仓、治理仓里就是**绝大多数单**。

三层放大:

1. **本仓自己把闸调到了极窄**:`docs/babysit.md` 必须先问档第一行把 `kit/` `playbook/` `bench/` `boot/` `cli/` `skill/` `hooks/` `AGENTS.md` 的语义改动全括进去,并自注「**本仓绝大多数 PR 在此**」。当初的理由成立(这里的内容就是方法论本身),但叠加上「内容不看拍板记录」这一条,结果是值守「少让用户拍板」那半个目标**在本仓恒等于零**。
2. **预授权机制从未被激活,而且没人发现**:`MERGE-POLICY.md` §3 第 4 类要求「值守要在文档 §5 记一行——哪一类、哪天拍的」。查 `docs/babysit.md` §5 遗留清单:**零条**这样的记录。机制挂了几个版本,一次都没启用过,因为**没启用不触发任何闸,也不产生任何报错**。
3. **与前一天刚立的规矩打架**:`playbook/multi-contributor-protocol.md` 三½.7 配套 1「授权幂等:同类动作一次点头长期有效,不逐次追问」——同一套方法论两处口径拉反方向,正是[案例 39](39-harness-boilerplate-as-project-rule.md) 自己写下的病名,当时没把 merge 本身算进去。

## 修法
判据补一维:**合并这个动作本身产生新决定吗?** 不产生 = 机械步骤。

- 默认合入档加一类「**内容已拍板的单**」:用户本人拍过内容,且拍板**在 git 里核得到**(PR 描述「拍板」段 · `decision(...)` commit · CHANGELOG 未发布条目 · `snapshot/` 快照,四选一),且**实际 diff 不超出拍板范围**;核不到 / 超范围整单降级。
- 必须先问档划出**永不被覆盖的五类**:权限配置 · 不可逆动作(迁移/清洗)· 删远端分支或关别人的 PR · 跨仓跨账号外向操作 · 带 breaking 或迁移标注。它们进这一栏的理由不是「用户要知道」,是「撤不回来 / 动的是别人的东西」,拍过板也不改变。
- 区分**常驻预授权**(写进 git 的条款,直接认)与**单次转述**(聊天记录里带过来的一句「合了吧」,仍须本人复核)。原先那条「批准只认本会话内的用户输入」管的是后者,一字未松。

## 可复用规则
1. **同一个决定不问第二遍**。授权判据要看「这一下按下去会不会产生新决定」,不能只看「碰了什么文件」。第二遍问不出新信息,只制造噪音——而噪音会淹掉真正该问的那一次。
2. **预授权必须落进 git,不能只活在聊天记录里**。值守 / 巡检 / 定时任务这类**按班次开会话**的角色,换一班就换一条会话,聊天记录不跟着走。授权只活在某一班的上下文里 = 每次换班都要用户重说一遍,机制自己把自己耗光。
3. **「挂好等授权」的机制要有激活证据**。写了清单但从没被启用过,不触发任何闸、不产生任何报错,可以静默失效很久。给这类机制配一条可查的激活痕迹(记在哪一行、哪天拍的),巡检时对得上才算在跑——对不上就是没在跑。
4. **松一条规矩时,先分清它原本管的是哪两件事**。「批准只认本会话内输入」同时兜着「转述不算授权」和(被误读成)「条款也要每班复述」;拆开之后,松掉后者不动前者,地基一寸没让。
5. **中央化的机制要能说出自己省了什么**。合并权中央化省的是 O(N²)→O(N) 的 rebase,以及用户的拍板次数;当第二样恒为零时,用户会正确地问「那岂不是没有作用了么」——**这不是抱怨,是机制审计**。
