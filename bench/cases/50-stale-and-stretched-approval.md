# 案例 50：旧批次的一句「你来决定吧」被拿去改冻结面 —— 值守拦下的正例

> 层级：L2 | 来源：Dartify 2026-09-26 结账（stale-approval-not-portable-across-batches）| 入册：2026-09-26 | 性质：**正例**（机制接住了）

## 症状

- 2026-09-26 Dartify PR #302（第六批，字重 w800→w700）。作者会话把 09-25 第四批里用户的一句「如果效果可以改回来的话，你来决定吧」——原语境是**安卓样式怎么处理**——外延成了授权，改掉了四处**用户签过字的冻结面**（schedule-v2 快滚 HUD / 日轨日号、today-heatmap 月格今天、月份选择当前月）。
- PR 悬点栏写着「没有待用户拍板的开放项」。按形式面，这张单会进免问合并档。
- 值守核对时按 CONTRIBUTING §四② 和「转述 ≠ 批准」把它拦下，没走免问档，转回给用户。用户在作者窗口回「同意1」、在值守窗口回「合 302」之后，09:00:01Z 合入；记账 `e0f8120a`（#303）写明了先问档的缘由和授权来源。

## 根因

**授权被当成可以携带的东西。** 一句授权有它的语境：哪一批活、哪个问题、哪几个选项。作者会话把它从原语境里拎出来，一是**跨了批次**（第四批 → 第六批），二是**扩了范围**（安卓样式 → 冻结面）。再加一句「没有待拍板项」的自述，形式面就全绿了——调度只看形式面，看不出授权是借来的。

已落地的「转述 ≠ 批准」（2026-08-17）管的是**谁说的**；这次暴露的是另外两种：**什么时候说的**、**说的是什么**。

## 修法

- 值守侧：核拍板指针时，三种冒牌一律不认——转述的、过期的、外延的；条款没写到的冻结面回到逐单先问；作者的「无待拍板项」自述不构成授权（kit/babysit/MERGE-POLICY「批准的两种载体」）。
- 作者侧：要动冻结面，能问就开工前一次问清（给选项 + 推荐）；不能问就照做，但列进「要你拍」，不引用旧批次的授权（kit/output-contract §3）。

## 可复用规则

**授权只在给出它的那一批、那个问题里有效。** 三种冒牌：转述的（谁说的不对）、过期的（什么时候说的不对）、外延的（说的是什么不对）。核拍板时问三句：是用户本人在这里说的吗？是为这一批说的吗？说的就是这件事吗？
