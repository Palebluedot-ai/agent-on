# 案例 45：闸把账算到别人头上 = 恒红（有记录 ≠ 有人）

> 层级：L2 | 来源：用户 2026-09-14 反馈 + Orbit / Dartify / 本仓三处旧记忆 | 入册：2026-09-14

## 症状

用了 agent-on 的项目里，「某个 worktree 没登记」就让**所有**窗口 commit 不了，全变红；`git worktree remove` 掉一棵树之后登记还在，又红；值守窗口关了没 `release`，其他窗口的合并被一个不存在的窗口锁着。三个项目各自留下了「解锁配方」记忆——一个需要配方才能日常使用的闸，本身就是症状。

## 根因

**两处闸都把「有一条记录」当成了「有一个活人」。**

- 边界闸的失败条件是全场性的：任一未登记树 / 任一越界 / 任一 OVERLAP / 任一幽灵登记 → 全场 FAIL。而桌面宿主每开一个会话就自建一棵树、从不登记，所以「全场有一棵没登记的树」是常态，红灯就成了常态。红的那个人往往不是肇事者，也没有权限清理别人的树（案 40 已经写过成本归属，但当时选择了保留连坐）。
- 值守登记只检查「目录还在不在」。窗口关了目录当然还在，于是登记永远「在班」，直到有人手动 `release --force`。本仓实测一条登记锁了 26 天。

共同点：**恒红的闸没有信号**（本仓 2026-08-20 自己立的话），而恒红的成因不是配置没调好，是判据把「记录」当成了「事实」。

## 修法

- 边界闸只留一条红：**本树未提交的改动进了别的活轨的 owns**，只拦本树。未登记、幽灵登记、纸面重叠、无人持有的越界、休眠脏树，一律降为提示行。主树不再按身份当控制轨，按它碰没碰活轨的地盘判。
- 值守登记加心跳：值守窗口每次经 guard 的工具调用自动续；超过失效窗口（默认 90 分钟）没心跳，登记自动失效，闸 fail-open，接班不用 `--force`。

## 可复用规则

**闸的判据只能是「此刻有没有人在这里做这件事」，不能是「有没有一条记录说曾经有人」。** 记录会过期、目录会残留、树会被宿主自动建出来——凡是靠一条静态记录判「有人」的闸，随时间只会单向变红。两个必要的补丁：①红灯只算到**当事的那棵树 / 那个窗口**头上，别人的状态只进报告；②记录必须有**活性证据**（心跳、mtime、进程），并且有到期。

**反向自检一句**：把闸报的每一条红，问「谁现在正在做什么才触发了它」——答不出「谁」和「正在」这两个词，那条红就该降成提示。
