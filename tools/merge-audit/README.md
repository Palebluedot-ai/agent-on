# merge-audit —— 值守自动合并的独立审计员

> 职责边界：本工具**不合并任何东西，也不阻止任何东西**。它只判断、只记录、只点名。
> 真正按下合并的是值守会话；本工具的价值全部来自**独立**——它从 GitHub 的客观事实重新算一遍，
> 不读值守对自己行为的任何自述。
> 授权口径的散文版在 [../../kit/babysit/MERGE-POLICY.md](../../kit/babysit/MERGE-POLICY.md)；
> 机器可执行的那份就是本目录的 [policy.json](policy.json)。**两份对不上时以 policy.json 为准**——
> 它是跑起来的那一份。

## 为什么存在

2026-08-20 用户拍板：值守从「除清单内的几类外一律先问」翻成「除硬停清单外一律自动合」。
**把事前审批拿掉，就必须把事后检测补上**，否则中间那段是裸奔。

本工具就是那个事后检测。它假设值守会犯错、也假设值守可能给自己的越界找出漂亮理由，
所以它**不听值守怎么说**，只看 GitHub 上留下的事实：谁写的、改了哪些文件、
检查是什么结论、评审是什么结论。

## 三个动作

```bash
python3 tools/merge-audit/merge_audit.py precheck --pr 42   # 合之前，判一次
python3 tools/merge-audit/merge_audit.py record --pr 42 --action merged --claimed AUTO
python3 tools/merge-audit/merge_audit.py report              # 事后，独立重判并点名
```

| 动作 | 谁跑 | 什么时候 | 回答什么 |
|---|---|---|---|
| `precheck --pr N` | 值守 | 合之前 | 这单能不能自动合？（退出码 0 / 10 / 20） |
| `record --pr N …` | 值守 | 合之后立刻 | 我按什么判的、我干了什么 |
| `scan` | 谁都行 | 任何时候 | 从 GitHub 真相独立重判已合并的单 |
| `report` | 值守每轮 / 用户随时 | 任何时候 | 自述和事实对得上吗？对不上点名 |
| `policy` | 谁都行 | 任何时候 | 现在到底按什么规则在跑 |

`precheck` 的退出码就是分流表：

```text
0   自动合，合完 record 一行即可，别出声
10  自动合，但本轮面板必须写一行让用户看见
20  不许自动合 —— 命中硬停清单，或者健康度红（评审 changes-requested / 检查红）
2   工具自己出错（gh 没装 / 没登录 / 网络断）—— 按 fail-closed 处理，当它是 20
```

## 四种被点名的形状

| 级别 | 什么意思 | 为什么它值一次告警 |
|---|---|---|
| `VIOLATION` | 硬停清单命中，却已经合了 | 越界。最重 |
| `MERGED_RED` | 评审 changes-requested 或检查红着合了 | 越界 |
| `UNRECORDED` | 合了，但账本里没有对应记录 | **比合错更危险**：悄悄合的，事后谁都说不清当时按什么判的 |
| `MISMATCH` | 值守自称的档位 ≠ 独立重判的档位 | 自我合理化的指纹 |
| `LEDGER_BROKEN` | 账本哈希链断了 | 有人改写或删掉了历史记录 |
| `NOTABLE` | 属于需播报类 | 不是错，但用户该看见一行 |

`report` 的退出码：发现里最重的一条 ≥ `--fail-on`（默认 `MISMATCH`）就返回 1。
`NOTABLE` 默认不算失败——它是「说一声」，不是「出事了」。

## 账本

默认落 `ledger/merge-audit.jsonl`（跟着 git 走，可 review、可回溯、换机器不丢）。

**追加写 + 哈希链**：每条记录带上一条的 sha256 前 16 位。悄悄删掉或改写一条历史记录，
链就断了，`report` 会报 `LEDGER_BROKEN` 并指出断在第几行。这不是防篡改（能改文件就能重算整条链），
是**防「不留痕地改一条」**——把静默修改变成必须公开的重写。

`policy.json` 里的 `ledger_starts_at` 是记账起点：这之前合入的单不产生记账类发现
（那时还没有账可对，永久报它们只会训练人忽略这份报告），但**越界类发现不受此限**。

## 规则住在哪

全部在 [policy.json](policy.json)，改它就是改值守能自动合什么。所以：

**`tools/merge-audit/**` 自己就在硬停清单里。** 被监控者不许改监控自己的东西——
值守要动这个目录的任何一行，都得先问用户。这条不是形式主义：
如果 agent 能悄悄把自己从清单里删掉，上面所有机制一起失效。

三类硬停之外还有一条 `untrusted-author`：作者不在 `trusted_authors` 里的 PR 永不自动合，
哪怕它只改一个 typo（供应链）。

## 工具看不见的那半（诚实边界）

本工具看的是**「合了什么」**，不是**「值守都干了什么」**。以下动作不是 PR 形状的，
本工具一概看不见，它们照旧归纪律清单、照旧必须问用户：

- 删远端分支 · 关闭别人的 PR · force-push · 删/重打 tag
- 数据库迁移、数据清洗等仓外的不可逆动作
- 跨仓 / 跨账号的外向操作（评论、webhook、邮件）

值守做这些时用 `record --action held` 之类留一行，但**没有独立复核**——
这一半仍然靠纪律，不靠机器。写在这里是为了别让人误以为装了工具就全覆盖了。

另外两条：

- **规则是启发式，不是证明**。路径 glob 与结构化标记能抓住绝大多数形状，抓不住「文档里
  写了一句危险的话」这种语义级越界。它降低风险，不消灭风险。
- **`--deep` 才扫 diff 里的密钥模式**，`scan` 默认不扫（一条 PR 一次 `gh pr diff`，慢）。
  没扫的那一轮会在输出里自己说明，不假装扫过。
- **密钥扫描按文件归属**，证据会说清在哪个文件；`policy.json` 的 `diff_exclude_globs`
  只排掉 `tools/merge-audit/**`——规则定义与它们的测试夹具必然包含模式本身
  （`policy.json` 里就写着 `AKIA[0-9A-Z]{16}`）。这个目录本来就被硬停第 1 类拦着。
  **别往这个排除清单里加业务目录**，那才是真会漏密钥的地方。
