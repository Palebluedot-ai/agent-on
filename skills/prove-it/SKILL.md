# Prove It — 防假绿验证协议

本技能用于消灭“测试 100% 绿灯但线上照样坏”的完成幻觉：确保验证穿过真实业务代码、能抓出目标错误、并与即将交付的提交完全一致。

## 执行步骤

### 1. 锁定真实业务入口与正反预期（Entry Check）

1. 从需求列出可核对的**正向结果**（用户操作后产生什么状态/输出）与**反向不变量**（未确认前不能提前写库、无权限时必须拒绝、空兜底不能抹掉已有提取结果）。
2. 在业务源码中定位真正对用户生效的入口函数、接口处理器或界面组件，确认测试直接调用该入口：
   - 若测试文件内部自己重新拼装了一套近似逻辑，只算测了测试代码自己，必须改为调用真实模块。
   - 若使用了录制回放或替身（mock/stub），核对替身返回的字段和写入的属性在真实运行库中确实存在，避免“替身比线上更慷慨”。

**完成判据**：每项变更都能点名测试实际穿过的业务入口符号，且不依赖自造逻辑副本。

### 2. 执行错误对照与判别式探针（Counterfactual Red → Green）

针对本次修改的核心逻辑、修复的缺陷、安全边界或结构化配置，做一次反向证伪：

1. **代码与状态修复**：在干净本地状态中临时注释/改坏本次关键修复或守卫条件（或切回修复前逻辑跑新测试），运行目标测试并确认它**因预期原因变红（RED）**；随即完整恢复代码并重跑，确认恢复为**绿灯（GREEN）**。
2. **结构化配置与模块接线**（`TOML` / `YAML` / `JSON` / 路由挂载 / 共享组件）：
   - 走真实解析器或结构位置断言（不靠纯文本 `grep` 字符串存在）；
   - 新共享组件/配置必须有一条穿过真实消费方的接线断言，临时断开接线时断言必须变红。
3. **模型约束 / 外部 Schema 校验**：使用**判别式探针**（例如在测试 Schema 中放入提示词从未提及的特征枚举值或随机标记），只有输出原样命中该标记才算约束生效；不把“压力测试下恰好没违规”当作约束生效的充分证据。

> 低影响纯文案微调无需强造错误对照；凡行为、权限、数据、解析、并发与配置改动均执行本步。

**完成判据**：亲眼观测到“注入故障 → 目标断言报红 → 恢复代码 → 重新变绿”的完整闭环。

### 3. 核对持久态回读与交付链一致性（Read-Back & Delivery Chain）

1. **写入后独立回读**：涉及数据库、缓存、文件落盘或网关写入时，在写操作返回成功后通过独立读取接口核对实际保存内容与记录条数，不只看 HTTP 200 或函数未抛异常。
2. **保留真实退出码**：执行测试与静态检查命令时不接吞退出码的管道（不用 `test_cmd | tail`；确需管道时显式 `set -o pipefail`）。
3. **核对交付链落差**：运行 `git status -sb` 与 `agent-on wt`（若未装 CLI 则运行 `git rev-list --left-right --count origin/main...HEAD`），确认当前验证的提交、未暂存文件与即将打包/推送的工作树完全一致，未落在落后主线的陈旧分支上。

**完成判据**：取得未截断的真实命令退出码、状态回读结果及当前分支与主线的准确落差。

### 4. 输出精简可核验的验证回执

向用户交付或写入 PR 说明时，按以下结构交代事实（简单改动可合并成一段连贯说明，不填无意义的空话）：

```text
验证对象：<分支 / HEAD SHA / 落后或领先主线提交数 / 运行环境>
真实入口：<测试实际调用的业务模块、接口或界面路径>
错误对照：<临时注入了什么错误 → 哪条检查变红 → 恢复后通过>
真实与替身边界：<哪些走了真实代码/数据库回读，哪些外部依赖使用了替身>
未覆盖范围：<尚未执行的平台、真机或线上外部服务及其影响>
```

**完成判据**：读者无需翻聊天上下文，即可仅凭回执分清哪些已由真实代码证伪通过、哪些仍待后续环境验收。
