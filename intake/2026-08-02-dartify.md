### scanner-green-must-be-read-with-scope(扫描类工具的「通过」必须连同「扫了什么」一起读,静默降级会伪装成合格)
- source:Dartify @ 33d3d3c | pin v0.5.1
- evidence:在 git worktree 里跑 `gitleaks detect --source <worktree>`,因 worktree 的 `.git` 是**指针文件不是目录**,工具先打 `ERR fatal: not a git repository` 再打 `INF no leaks found`、**exit 0**——只读末行会得到「扫过且干净」的错误结论。改 `--no-git` 重扫才是真扫(**2.25s vs 8.1ms**,耗时本身就是范围指标)。同族第二例:CI 里 Docker Hub 拉镜像超时(`context deadline exceeded`)让 gitleaks job 变红,在 checks 面板上与「扫出密钥」长得一模一样,已拆两步 + 拉取重试(`33d3d3c`)
- confidence:high(两次运行输出对照 + 一次真实 CI 事故)
- claim:任何扫描/检查类工具的结论,必须同时读**范围指标**(文件数 / 耗时 / 目标数)再采信——`exit 0` 与末行「通过」都可能来自「压根没跑起来」。CI 里把**取工具**与**跑工具**拆成两 step,否则基建假红与真实发现同形,会训练出「红了先当没看见」
- suggested_landing:playbook/anti-hallucination.md 第六型新增「工具静默降级」;kit 的 CI 模板给扫描类 job 拆两 step
- rollback:revert 落地 commit
